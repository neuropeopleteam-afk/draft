# LLM: цепочка моделей

Код: `backend/app/modules/llm/client.py` (цепочка, автомат-выключатель, ретранслятор), `assessment/grader.py`
(оценка открытых ответов, вторая оценка), `matching/need_parser.py` (разбор потребности), `resume/extract.py`
(резюме), `resume/pii.py` (вырезание ПДн). Тесты — `backend/tests/test_llm_chain.py` (подменённый транспорт httpx,
без сети). Прогоны — `tools/llm/`, результаты — `docs/llm/`.

## 1. Какая модель где и почему

| Функция | Цепочка (сервер, `LLM_CHAIN=openrouter,yandex`) | Тайм-аут | Рассуждения | Почему |
|---|---|---|---|---|
| `parse_need` — разбор вакансии | Claude Sonnet 5.5 → yandexgpt-5.1 → правила | 25 с | low | Sonnet: лучшая полнота стека среди ответивших на все 50 вакансий, 2,7 с; yandexgpt-5.1 — самая быстрая и надёжная запасная (раздел 6) |
| `resume` — разбор резюме (после вырезания ПДн) | Claude Sonnet 5.5 → yandexgpt-5.1 → словари | 25 с | low | та же задача извлечения, тот же выбор |
| `grade` — оценка открытого ответа | Claude Sonnet 5.5 → `LLM_GRADING_MODEL` (Yandex) → «на проверке» | 40 с | по умолчанию модели | на наборе оценщика: 0 из 116 атак проходят, порядок сильный > средний > слабый на 29 из 29 заданий, 2,7 с |
| `grade_second` — вторая оценка спорных | Claude Fable 5.1 → `LLM_GRADING_MODEL` → эксперт | 40 с | low | другая модель (независимая ошибка); вызывается для 16 % ответов (раздел 4) |

Без новых переменных поведение прежнее: один провайдер `LLM_*` (Yandex AI Studio), модель `LLM_MODEL`, оценка —
`LLM_GRADING_MODEL`, второй оценки нет (та же модель — не независимая).

Последний рубеж у каждой функции — путь без LLM: словарь стек-тегов и правила (разбор), статус «на проверке» и
эксперт (оценка). Интерфейс показывает, какая модель фактически ответила: «разбор: словарь + Claude Sonnet 5.5,
цитаты проверены», при переходе — имя запасной, если не ответил никто — «разбор по словарю: модель не ответила».
Цитата из вакансии подписана моделью, которая её нашла. В журнале проверки (экран эксперта) — обе оценки с именами
моделей.

## 2. Цепочка и автомат-выключатель

- Порядок — `LLM_CHAIN` (`openrouter,yandex`; провайдер без ключа пропускается). Переход к следующему: ошибка
  сети, тайм-аут, HTTP ≠ 200, ошибка в теле ответа, пустой ответ, невалидный JSON, ответ не прошёл проверку
  вызывающего (`validate`: например, у оценки нет балла по всем критериям). Причины — в `attempts` результата.
- Разбор JSON терпим к «поправкам»: если модель вывела объект, затем «Поправка: …» и второй объект — берётся
  последний целый объект; обрезанный ответ остаётся невалидным (переход дальше), внутренние объекты не берутся.
- Автомат-выключатель на пару «провайдер:модель»: `LLM_BREAKER_FAILURES` ошибок подряд (3) → пропуск
  `LLM_BREAKER_COOLDOWN_S` секунд (60), затем одна пробная попытка; успех закрывает автомат, ошибка — снова открывает.
  Недоступная модель второй оценки не выключает основную модель того же провайдера. `0` — автомат выключен.
- Модель, тайм-аут и усилие рассуждений — на функцию: `LLM_MODEL_<FUNC>` (`модель` — для первого провайдера цепочки
  или `openrouter=…,yandex=…`), `LLM_TIMEOUT_<FUNC>`, `LLM_REASONING_<FUNC>` (`low | medium | high | default`).
  У Sonnet 5.5 рассуждения не выключаются (HTTP 400), поэтому `low`: на длинной вакансии с рассуждениями по умолчанию
  827 из 1200 токенов ушли на рассуждения и JSON обрезался; с `low` — 0 токенов рассуждений, ответ вдвое дешевле.
- Общий бюджет оценки одного ответа — `LLM_GRADING_BUDGET_S` (50 с): первая и вторая оценка с переходами по цепочке
  укладываются в `proxy_read_timeout` nginx (60 с), ответ кандидата ждёт оценку синхронно. Не хватило времени на
  вторую оценку — ответ «на проверке» (повтор при завершении теста, затем эксперт).
- `/api/meta` → `llm`: `chain` (провайдеры, настроен ли, через ретранслятор ли), `functions` (модели по порядку,
  тайм-аут), `breaker` (открытые автоматы), `last` (кто ответил последним по функции и был ли переход). Ключей,
  адреса ретранслятора и каталога Yandex Cloud там нет; прежние поля `configured`, `provider`, `model` сохранены.

## 3. OpenRouter и ретранслятор

- Ключ — `OPENROUTER_API_KEY` (файл `OPENROUTER_ENV_FILE`, на сервере `/opt/spectrek_fsp/secrets/openrouter.env`).
  Заголовки атрибуции нейтральные: `HTTP-Referer: https://localhost`, `X-Title: llm-client` — без названия
  продукта и домена (тест). В теле — `provider.data_collection = deny` (провайдеры, хранящие запросы для обучения,
  исключаются).
- Ретранслятор: OpenRouter определяет страну исходного запроса, с сервера в РФ — 403. Если задан `LLM_RELAY_URL`,
  клиент ходит на него (базовый адрес OpenAI-совместимого API уже с `/api/v1`, клиент добавляет
  `/chat/completions`) и добавляет `X-Relay-Token: LLM_RELAY_TOKEN`; ключ OpenRouter — в `Authorization` от
  клиента. Оба значения — в `LLM_RELAY_ENV_FILE` (`/opt/spectrek_fsp/secrets/llm_relay.env`). Проверено из
  песочницы: Sonnet через ретранслятор отвечает (3,5 с на коротком запросе, напрямую — 2,0 с), неверный токен — 404.
- В docker-compose `openrouter.env` и `llm_relay.env` — необязательные `env_file` (как `llm.env`): нет файла —
  цепочка без OpenRouter.

## 4. Вторая оценка спорных ответов

Спорный ответ (`grader.doubts`, любое из условий):

- `near_threshold` — балл у порога зачёта: |x − 0,5| ≤ `LLM_GRADING_NEAR` (0,05);
- `level_mismatch` — уровень модели не согласован с баллом (weak при x ≥ 0,5 или strong при x < 0,5);
- `soft_signals` — мягкие признаки инъекции (обращение к проверяющему, «ответ сверен с эталоном», самооценка);
  жёсткие (`injection_signals`) в модель не уходят вовсе — сразу эксперту;
- `low_relevance` — высокий балл при слабой связи ответа с заданием.

Вторая оценка — независимый вызов другой модели (`grade_second`, Claude Fable 5.1): критерии и эталоны в обратном
порядке (против эффекта порядка), первая оценка не передаётся. Правило объединения консервативное:

- |x₁ − x₂| ≤ `LLM_GRADING_DISAGREE` (0,25) → среднее по каждому критерию, метод `llm2`;
- расхождение больше, вторая оценка не получена или не уложилась в бюджет → балла нет, ответ «на проверке»
  (`graders_disagree` / `second_opinion_failed`), решение за экспертом;
- вторая оценка вызывается, только если её модель отличается от модели первой (без цепочки поведение прежнее).

Обе оценки, модели и причины сомнения сохраняются в `grading` ответа (`scores`, `second`, `checks`, `model_label`) и
видны эксперту: «Две оценки: Claude Sonnet 5.5 0,50 и Claude Fable 5.1 0,75».

Доля вызовов: порог 0,05 выбран по первому проходу Sonnet на наборе оценщика (406 ответов, 357 дошли до модели):
0 → 14 %, 0,05 → 16,5 %, 0,1 → 18 %, 0,15 → 27 % вызовов. С 0,05 вторая оценка понадобилась 64 ответам из 406
(15,8 %; ориентир карточки 10–20 %): у порога — 60, мягкие признаки — 5, уровень не согласован — 4. Fable согласна в
59 случаях (|Δ| в среднем 0,07), расходится в 5 → эксперту (1,9 % честных ответов).

## 5. Персональные данные

В модель уходит только обезличенный текст (`resume/pii.py`, `redact`):

- резюме и открытый ответ — ФИО (NER), email, телефон, ссылки на профили и мессенджеры (GitHub, GitLab, GitFlic,
  LinkedIn, hh.ru, Хабр, Telegram и `@ник`, VK, LeetCode, Stack Overflow, Kaggle, Codeforces, X/Twitter,
  Behance, Dribbble);
- вакансия — плюс контактные лица после подсказок «Рекрутер — Пётр Сидоров», «HR: Ольга», «Контактное лицо: …»
  (на 50 реальных вакансиях — 0 ложных срабатываний; NER по всему тексту давал 12, например «Гибрид»), а также
  признаки ст. 64 ТК РФ (маскируются до вызова).

Тесты (`test_no_pii_in_*`) перехватывают тела запросов к модели при разборе вакансии, загрузке резюме (PDF через
API) и оценке ответа и проверяют, что ни ФИО, ни email, ни телефон, ни ссылки на профили туда не попали.

## 6. Качество / время

### Разбор 50 реальных вакансий И8

`tools/llm/bench_needs.py`, корпус `docs/realdata/vacancies_50.json`, разметка silver (модель + ручная сверка, не
экспертная). Путь продукта целиком (вырезание ПДн → модель → проверка цитат → слияние с правилами), одна попытка на
текст без перехода, тайм-аут 25 с. «Модель + правила» — итог продукта; «только модель» — извлечённое моделью после
нормализации (по текстам, где модель ответила). Время — ответ модели. Результаты — `docs/llm/needs_bench.json`.

может быть недоразмечена, это проверит экспертная разметка. Стоимость Sonnet — 0,33 $ на 50 вакансий
(≈ 0,7 цента на разбор). Невалидных цитат — 0 у всех.

Запасная Yandex — **yandexgpt-5.1/latest**: ответила на все 50, быстрее всех (медиана 2,4 с против 7,4 с у текущей
yandexgpt/latest), стек полнее текущей (R 0,960 против 0,947, «только модель» 0,62 против 0,57). gpt-oss-120b
извлекает больше (0,79), но в 4 раза медленнее, p90 17 с и 1 тайм-аут; deepseek-v4.1-flash извлекает лучше всех,
но не укладывается в 25 с в 38 % случаев; qwen3.6 при лимите 2500 токенов в половине случаев обрезает JSON
рассуждениями. Альтернатива при запасе времени: gpt-oss-120b с тайм-аутом 30 с.

Порядок «сильный > средний > слабый» — 29 из 29 заданий во всех условиях. Sonnet строже панели: смещение к эталону
на ответах gpt-oss-120b −0,16 (yandexgpt +0,07), средний эталон 0,45 при ожидании ≈ 0,5 (yandexgpt 0,54), и ни одна
атака не проходит. Вторая оценка у порога немного сближает с эталоном (MAE 0,178 → 0,170 на A) ценой 16 % вызовов
Fable. Стоимость: первая оценка — 0,8 цента на ответ, вторая (Fable) — около 6 центов на спорный ответ.

Две находки прогона уже исправлены в коде: 20 из 406 ответов Sonnet содержали после JSON «Поправку» со вторым
объектом (прежний разбор считал их невалидными — теперь берётся последний целый объект); Fable с рассуждениями по
умолчанию и лимитом 1500 токенов обрезала 16 из 41 ответа (теперь рассуждения low и лимит 3000; эти ответы получены
повторно с новой настройкой, медиана 9,5 с вместо 18,7 с).

**Оговорка.** Разметка атак E1–E3 и часть ответов набора сделаны моделью семейства Claude, поэтому согласие Sonnet и
Fable с ней может быть завышено. Эталон — модель gpt-oss-120b, а не эксперты; итоговый выбор модели-оценщика — по
согласию с экспертной разметкой (раздел «Экспертная разметка» на /validation).

## 7. Как воспроизвести

```bash
# ключи — только в окружении процесса
python tools/llm/bench_needs.py --models openrouter=anthropic/claude-sonnet-5.5,yandex=yandexgpt-5.1/latest \
    --out docs/llm/needs_bench.json
# набор оценщика: во временной копии feat/integrity
python -m app.modules.validation.grader_check build --cond v2 --out /tmp/g/v2_1.jsonl
python tools/llm/chain_runner.py --requests /tmp/g/v2_1.jsonl --out /tmp/g/v2_1_out.jsonl \
    --model openrouter=anthropic/claude-sonnet-5.5 --func grade
python -m app.modules.validation.grader_check second --req /tmp/g/v2_1.jsonl --res /tmp/g/v2_1_out.jsonl \
    --out /tmp/g/v2_2.jsonl
python tools/llm/chain_runner.py --requests /tmp/g/v2_2.jsonl --out /tmp/g/v2_2_out.jsonl \
    --model openrouter=anthropic/claude-fable-5.1 --func grade_second --max-tokens 3000
python -m app.modules.validation.grader_check report --dir /tmp/g
```
