# Голосовой ввод потребности («Надиктовать»)

Работодатель может не печатать, а надиктовать, кого ищет: кнопка «Надиктовать» стоит у поля «Кого вы ищете» на экране
`/employer/needs` (туда же ведёт проводник жюри). Речь распознаётся в текст, текст появляется в поле, его можно
поправить, а дальше — прежний разбор с цитатами по кнопке «Разобрать требования». Голос — ещё один способ заполнить
поле, сам разбор и подборка не меняются.

Всё за флагом `VOICE_NEED_ENABLED` (по умолчанию выключен): при выключенном флаге кнопки нет, маршрут отвечает 409.

## Как это работает

1. «Надиктовать» → панель согласия (один раз за вкладку): что запись уйдёт на распознавание речи поставщику через наш
   сервер и сразу удаляется, ничего не сохраняется, разбор начнётся только по кнопке, имена и контакты не называть.
   «Согласен, включить микрофон» или «Ввести текстом».
2. Браузер спрашивает разрешение на микрофон. Без явного согласия на шаге 1 микрофон не включается.
3. Запись не дольше 60 с: таймер «0:12 из 1:00», индикатор уровня сигнала, «Стоп» и «Отменить». На 60-й секунде запись
   останавливается сама.
4. После «Стоп» запись целиком уходит на сервер (`POST /api/employer/needs/voice`), сервер передаёт её функции
   распознавания движка интервью (`stt`, Deepgram через ретранслятор) и возвращает текст.
5. Текст дописывается в поле (если там уже был текст — через пробел), фокус переходит в поле. Под кнопкой —
   «Текст распознан и добавлен в поле — проверьте и поправьте… Разбор начнётся по кнопке «Разобрать требования»».
   Ничего не разбирается, не сохраняется и не отправляется само.

Запись и общий хук микрофона — общий компонент `frontend/src/components/voice/` (useVoiceRecorder: getUserMedia,
MediaRecorder, уровень сигнала), тот же, что в устной защите ответов (`docs/INTERVIEW.md`). Экран потребности —
`frontend/src/components/VoiceNeed.tsx` (`DictateNeed`).

## Сбои — всегда сообщение и клавиатура

| Что случилось | Что видит работодатель |
| --- | --- |
| Браузер не умеет записывать звук (нет MediaRecorder / getUserMedia, не HTTPS) | «Этот браузер не умеет записывать звук — введите текст с клавиатуры.» |
| Отказ в доступе к микрофону | «Доступ к микрофону не разрешён. Разрешите его в настройках сайта… или введите текст с клавиатуры.» |
| Нет микрофона | «Микрофон не найден — подключите его или введите текст с клавиатуры.» |
| Слишком короткая или пустая запись | просьба попробовать ещё раз или ввести текст |
| Распознавание не ответило за 20 с (504), поставщик недоступен или ответил мусором (503), сеть | текст ошибки сервера и «Ввести текстом» |

У каждого сообщения — кнопка «Ввести текстом»: фокус переходит в поле. Ошибка распознавания не стирает уже введённый
текст.

## API

`POST /api/employer/needs/voice?consent=<версия>&duration_ms=<мс>` — только роль «работодатель». Тело — запись целиком
(`Content-Type: audio/webm`, `audio/ogg`, `audio/mp4`, `audio/wav`, `audio/mpeg`, `audio/aac`; тип проверяется по первым
байтам, а не по заголовку). Ответ:

```json
{"text": "Нужен бэкенд-разработчик…", "stub": true, "seconds": 2.4, "chars": 182, "truncated": false, "note": "…"}
```

Проверки по порядку (коды ошибок — `detail.code`):

| Проверка | Ответ |
| --- | --- |
| флаг выключен | 409 `voice_need_disabled` |
| нет согласия текущей версии (`consent`) | 422 `voice_consent_required` |
| больше 20 записей в час на работодателя или 300 в сутки на установку | 429 |
| длительность по часам браузера больше лимита + 1,5 с | 413 `voice_too_long` |
| тело больше `VOICE_NEED_MAX_KB` (читается потоком, не целиком в память) | 413 `voice_too_large` |
| меньше 64 байт | 422 `voice_empty` |
| не аудио по первым байтам | 415 `voice_bad_type` |
| распознавание дольше `VOICE_NEED_TIMEOUT_S` | 504 `voice_timeout` |
| ошибка поставщика, сети, ретранслятора, неполный ответ | 503 `voice_unavailable` (не 500) |
| длительность по распознаванию больше лимита + 3 с | 413 `voice_too_long` |
| речь не распознана | 422 `voice_empty` |

Текст: пробелы схлопнуты, не длиннее 8000 знаков (как поле потребности), обрезка помечается `truncated: true`.

`GET /api/meta` → `voice_need: {enabled, max_seconds, consent_version, consent_text, stub}` — без ключей и адресов.

## Персональные данные

- Запись и распознанный текст не сохраняются ни в базе, ни в файлах, ни в журнале (тест проверяет журнал); потребность
  не создаётся — её создаёт только сам работодатель прежней кнопкой.
- В журнал попадают только коды ошибок.
- Согласие — версия `2026-10-10.v1`, сервер без неё запись не принимает; браузер помнит согласие до закрытия вкладки.
- При разборе текста действуют прежние правила: контакты вырезаются до отправки в модель, фильтр ст. 64 ТК РФ.

## Заглушка

`INTERVIEW_STUB=1` или нет `DEEPGRAM_API_KEY` — распознавание не вызывается, сервер возвращает фиксированный пример
(`stub: true`): «Нужен бэкенд-разработчик уровня middle. Обязательно Python, FastAPI и PostgreSQL, опыт от 2 лет.
Желательно Redis и Docker. Удалённо или гибрид, до 280 тысяч рублей.» Интерфейс пишет, что это заглушка, а не
распознавание. На заглушке идут e2e и тесты.

## Настройки

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `VOICE_NEED_ENABLED` | `false` | кнопка и маршрут |
| `VOICE_NEED_MAX_SECONDS` | `60` | длительность записи (5…180) |
| `VOICE_NEED_MAX_KB` | `2048` | размер записи (60 с opus ≈ 0,5 МБ, AAC Safari ≈ 1 МБ) |
| `VOICE_NEED_TIMEOUT_S` | `20` | ожидание распознавания |
| `VOICE_NEED_PER_HOUR` | `20` | записей на работодателя в час |
| `VOICE_NEED_DAILY` | `300` | записей в сутки на установку |
| `DEEPGRAM_API_KEY`, `INTERVIEW_STUB` | — | общие с движком интервью (`backend/app/modules/interview/engine/CONTRACT.md`) |

Ретранслятор движка должен пропускать `api.deepgram.com` (как для устной защиты).
