# Протокол симуляции продукта (зафиксирован до прогонов, 21.10.2026)

Что проверяем: точность вердикта «подтверждён / не подтверждён / нужен доп. этап» и грейда у **того же движка, что на
стенде** (BankEngine → AppCATSession → finish → вердикт → второй этап у границы), на реальном банке заданий, на
модельных кандидатах (не люди). Код — `backend/app/modules/validation/product_sim.py`.

## Зёрна (разведены)
- Подбор настроек — только `TRAIN_SEEDS = 1101…1110`.
- Отчёт — только `TEST_SEEDS = 2201…2210` (запрещено в `--phase train`; `--phase test` отказывается от зёрен обучения).
- Отчётный прогон на `TEST_SEEDS` для каждой опубликованной цифры — один, после выбора настроек.

## Популяция и мир
- θ ~ N(0; 1,3); заявленный грейд = истинный + {0, 0, 0, +1, +1, −1} (как в независимой модели аудита
  `docs/audit_2010/scripts/sim.py`); направление — равновероятно из видимых направлений; стек — 1–3 тега направления.
- Мир «calibrated» — истинные параметры заданий равны параметрам банка; мир «misspec» — трудность семейств сдвинута
  N(0; 0,5) логита, наклоны × lognormal(0; 0,25) (банк не откалиброван на людях; движок об этом не знает).
- Ответ части задания — Бернулли по 2PL с истинными параметрами и разбросом вариантов; время — логнормальное по модели
  времени банка; тексты не генерируются (оценка — по модели ответа; погрешность проверки развёрнутых ответов —
  отдельный сценарий `--rater-noise`).

## Кандидаты-настройки (обучение) и правило выбора
Перебираются настройки продукта (переменные окружения api), по одной от настроек стенда:
C0 стенд; C1 квота практических заданий и в дотестировании (`ASSESSMENT_CODE_QUOTA_EXT`); C2 = C1 + порог подтверждения
0,8 (`ASSESSMENT_CONFIRM_LEVEL`, вердикт и категория совпадают); C3 = C2 + z 1,64; C4 = C2 + SE-стоп 0,25;
C5 = C2 + до 20 заданий; C6 = C2 + порог второго этапа 0,5; C7 = C2 + второй этап до 10 заданий.
Правило выбора (до прогона): максимум точности итогового вердикта (после второго этапа) при ограничениях
«основная часть — p90 ≤ 60 мин», «всего — p90 ≤ 85 мин»; при равенстве (в пределах 0,5 п.п.) — меньше ложных
подтверждений. Можно добавить одну комбинацию лучших одиночных изменений — тоже на обучающих зёрнах.

## Поправка №2 — механика продукта и подача цифр (21.10.2026, вечер; записано ДО прогонов TRAIN этой механики)
Основание: решения оркестратора и владельца 21.10 (переписка «Победа» → А4), разбор А15, выписка А13. Банк для
итоговых цифр — замороженный банк А3 с консервативными наклонами (a = 1,0 у вопросов с выбором, 1,3 у практических;
решение штаба: «параметрами ничего не компенсируем, потолок показываем честно»).

### 2.1. Механика (продукт, `ASSESSMENT_VERDICT_RULE=sprt`)
1. **Решение по заявленному грейду — SPRT Вальда у его порога только по ответам**: H₁ θ = порог + δ против
   H₀ θ = порог − δ, модель ответа 3PL движка (угадывание c = 1/K по фактическому числу вариантов шага, 1/строк — у
   «строки с ошибкой», 0 — у вывода и текста), без априорного распределения (прежнее правило — апостериорная
   вероятность с априорным N(0; 1) — стягивало оценку к середине шкалы: ложные подтверждения у Стажёра/Junior).
   «Подтверждён» — LLR ≥ ln((1 − β)/α), «не подтверждён» — LLR ≤ ln(β/(1 − α)), между — «нужен доп. этап».
2. **Отбор заданий**: пока SPRT не решил — у порога заявленного грейда; затем — у ближайшего неопределённого порога
   («уровень по ответам»); критерий — информация 3PL (с угадыванием задания) на единицу ожидаемого времени
   (`ASSESSMENT_TIME_WEIGHT`). Квота ≥ 1/3 практических заданий — в каждой сессии (минимум, не потолок).
3. **Длина**: обычные пределы `ASSESSMENT_MAX_ITEMS` / `ASSESSMENT_MAX_MINUTES` (20 / 60) действуют, когда решение
   принято; у спорного порога — продление до 30 заданий / 90 минут (`ASSESSMENT_CONTESTED_*`, решение оркестратора).
   Досрочный стоп — решение принято и уровень по ответам определён (не раньше 8 заданий).
4. **Второй этап** (доп. этап заданиями, `two_stage`): только при «нужен доп. этап»; короткие задания у того же порога
   из новых семейств; итог — продолжение того же SPRT по ответам обеих сессий. Решения нет — **устная защита**, без
   «монетки» (прежний порог итога второго этапа 0,5 больше не участвует).
5. **Устная защита в симуляции** — консервативная модель, записанная до прогонов: 5 вопросов у порога, наклон 1,0, без
   угадывания (меньше информации, чем 5 практических заданий банка с a = 1,3). Решения нет и после неё — «не
   подтверждён: данных недостаточно» (считается как отказ, не как подтверждение).
6. **Уровень по ответам** (что видит кандидат и работодатель рядом с вердиктом): оценка уровня (`ASSESSMENT_POINT_
   ESTIMATOR`: WLE Уорма или EAP движка) → ступень; согласована с вердиктом: подтверждён → не ниже заявленного
   (выше — по `ASSESSMENT_UPGRADE_RULE`: sprt — на ступень выше, только если SPRT у следующего порога уверенно «выше»),
   не подтверждён → ниже заявленного, доп. этап — «предварительно».
7. **Античит (А6)**: правило «2+ сигнала / ловушка» переводит на доп. этап или устную защиту, не банит.

### 2.2б. Уточнение правила выбора (решение штаба 21.10, записано до просмотра результатов TRAIN поправки №2)
Критерий выбора настроек на TRAIN — **минимум потерь L = 3 · FC + FR** (FC — ложные подтверждения, FR — ложные отказы,
обе доли — от всех кандидатов; ложное подтверждение для работодателя хуже) при FC ≤ 2,5 % от всех; при равенстве потерь
в пределах 0,5 п.п. — больше точного грейда (итог), затем меньше минут. Рядом публикуется кривая FC–FR по всем
конфигурациям (для SPRT — по сетке α/β/δ; для прежнего правила — по порогам 0,5–0,9), кривая OC, метрики вне зоны
±0,25 и таблица по уровням заявки. Априорное распределение: решение и уровень по ответам — без априорного (SPRT и
WLE); вариант с оценкой EAP движка (`ASSESSMENT_POINT_ESTIMATOR=eap`) — одна из конфигураций TRAIN, тем же критерием.

### 3.7. TRAIN-раунд 2 — выбор одной конфигурации (план `docs/validation/TRAIN_PLAN_2110b.json`)
- Банк — голова ветки А3 на момент запуска (ближе к замороженному, чем банк раунда 1); зёрна TRAIN 1101–1110.
- Кандидаты (все с `ASSESSMENT_SUBPOOLS=1` — K0 хуже K1 по всем метрикам раунда 1): T0 — только это; T1/T2 — δ 0,45 /
  0,5; T3 — второй этап 12 заданий / 20 мин; T4/T5/T6 — T3 + δ 0,4 / 0,45 / 0,5; T7 — T3 + α 0,1; T8 — T5 + повышение
  выключено; T9 — T5 + продление у спорного порога до 36 заданий / 105 мин. Жёсткие условия, N = 1 500 на кандидата
  (150 на зерно), с повтором. Те же десять кандидатов в S-T-мире на TRAIN-зёрнах (S0–S9, N = 1 000) — разведка,
  в выборе не участвует.
- Правило выбора (до запуска): минимум L = 3 · FC + FR (обе доли — от всех кандидатов) при FC ≤ 2,5 %, p90 минут
  всего ≤ 105 и точном грейде (весь путь) не ниже T0 более чем на 1 п.п.; при L в пределах 0,5 п.п. — больше точный
  грейд, затем выше совпадение грейда при повторе, затем меньше минут. Если ограничениям не отвечает никто — T0.
- Решение — отдельным коммитом (env в `STAND_ENV` и строки для `.env` стенда — их применяет оркестратор) до FINAL.

### 3.8. FINAL — один прогон после «банк заморожен» от А3
