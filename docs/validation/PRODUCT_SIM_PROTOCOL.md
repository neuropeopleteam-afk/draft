# Протокол симуляции продукта (зафиксирован до прогонов, 21.10.2026)

Что проверяем: точность вердикта «подтверждён / не подтверждён / нужен доп. этап» и грейда у **того же движка, что на
стенде** (BankEngine → AppCATSession → finish → вердикт → второй этап у границы), на реальном банке заданий, на
модельных кандидатах (не люди). Код — `backend/app/modules/validation/product_sim.py`.

## Зёрна (разведены)
- Подбор настроек — только `TRAIN_SEEDS = 1101…1110`.
- Отчёт — только `TEST_SEEDS = 2201…2210` (запрещено в `--phase train`; `--phase test` отказывается от зёрен обучения).
- Отчётный прогон на `TEST_SEEDS` для каждой опубликованной цифры — один, после выбора настроек.

## Популяция и мир
- θ ~ N(0; 1,3); заявленный грейд = истинный + {0, 0, 0, +1, +1, −1} (как в независимой модели аудита
  `docs/audit_2010/scripts/sim.py`); направление — равновероятно из видимых направлений; стек — 1–3 тега направления.
- Мир «calibrated» — истинные параметры заданий равны параметрам банка; мир «misspec» — трудность семейств сдвинута
  N(0; 0,5) логита, наклоны × lognormal(0; 0,25) (банк не откалиброван на людях; движок об этом не знает).
- Ответ части задания — Бернулли по 2PL с истинными параметрами и разбросом вариантов; время — логнормальное по модели
  времени банка; тексты не генерируются (оценка — по модели ответа; погрешность проверки развёрнутых ответов —
  отдельный сценарий `--rater-noise`).

## Кандидаты-настройки (обучение) и правило выбора
Перебираются настройки продукта (переменные окружения api), по одной от настроек стенда:
C0 стенд; C1 квота практических заданий и в дотестировании (`ASSESSMENT_CODE_QUOTA_EXT`); C2 = C1 + порог подтверждения
0,8 (`ASSESSMENT_CONFIRM_LEVEL`, вердикт и категория совпадают); C3 = C2 + z 1,64; C4 = C2 + SE-стоп 0,25;
C5 = C2 + до 20 заданий; C6 = C2 + порог второго этапа 0,5; C7 = C2 + второй этап до 10 заданий.
Правило выбора (до прогона): максимум точности итогового вердикта (после второго этапа) при ограничениях
«основная часть — p90 ≤ 60 мин», «всего — p90 ≤ 85 мин»; при равенстве (в пределах 0,5 п.п.) — меньше ложных
подтверждений. Можно добавить одну комбинацию лучших одиночных изменений — тоже на обучающих зёрнах.

## Поправка до отчётных прогонов (21.10.2026, после прогона ботов)
Боты через движок показали, что ответы с угадыванием в вопросах с выбором (у 621 семейства априорная различающая сила
a = 3,0) дают ложные подтверждения: бот со случайными ответами получал Junior. Поэтому до отчётных прогонов:
1. Мир симуляции дополнен угадыванием (c = 1/K в частях с выбором варианта, 1/число строк — в выборе строки): так
   отвечают и люди; прежний мир без угадывания был оптимистичен.
2. «Junior (предварительно)» не считается подтверждением (считается отдельно).
3. Обучение повторено на тех же TRAIN_SEEDS для двух конфигураций: C8 (выбрана ранее) и C9 = C8 + оценка уровня с
   угадыванием (`ASSESSMENT_GUESSING_3PL`); правило выбора — прежнее. TEST_SEEDS по-прежнему не использованы.

## Итоговый прогон на банке стенда (решение оркестратора 21.10.2026, записано до итоговых результатов)
Записано, когда отчётные прогоны T1–T3 на банке `603474f` (1 504 семейства) были уже получены, а итоговый прогон ещё не
начат и банк для него не заморожен.
1. **Итоговые цифры** — один прогон по этому же протоколу (те же сценарии T1 calibrated N = 3 000 с повтором,
   T2 misspec N = 2 000, T3 rater-noise 0,1 N = 1 500, боты `cheat_bots` с теми же стратегиями и N) на банке, который
   будет на стенде при сдаче. Банк замораживается сообщением А3 «банк для цифр готов» (голова его ветки).
2. **Новые зёрна**: `FINAL_SEEDS = 4401…4410` (симуляция), `FINAL_SEED = 4501` (боты) — не использовались ни в одном
   прогоне. Настройки продукта — те же (C9, `STAND_ENV`), ничего не подбирается заново.
3. **До прогона** — отдельный коммит: голова ветки А3, `content_hash` банка из `BANK_SYNC.json`, команды запуска.
   Код отказывается от итогового прогона без `--expect-bank-hash` или при несовпадении хэша (`check_final_bank`).
4. **Выбора лучшего нет**: публикуется итоговый прогон, каким бы он ни вышел. Прогон на `603474f` (TEST_SEEDS, боты
   SEED 3301) — **запасной**: публикуется, только если итоговый не успеет к сдаче, с честным условием «банк 603474f,
   1 504 семейства; на стенде — банк <коммит>». Оба набора не смешиваются и не усредняются.
5. Повтор прогона допускается только при `engine_errors > 0` или падении контейнера — с записью причины в отчёт;
   повтор — на тех же зёрнах.
