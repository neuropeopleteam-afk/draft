# Подбор на реальных вакансиях hh.ru

**Тексты — реальные вакансии hh.ru, кандидаты — модельные (модель, не люди).** Корпус собран 2026-10-10: 414 вакансий девяти направлений (в прогоне 414, недоступно 0). Прогон 2026-10-11, код `62b9b213`, алгоритм `match-v1.3`. Пересчёт: `cd backend && DATABASE_URL=sqlite:///<демо-БД> python ../tools/realdata/hh_plus.py match` (демо-БД: `alembic upgrade head` + `python -m app.modules.demo.seed`).

**Методика.** Текст вакансии (название + описание) → разбор потребности путём правил (parse_need, без LLM) → подборка (build_selection, настройки по умолчанию) на демо-пуле: модельные кандидаты с результатами теста (модель, не люди). Метки — из полей hh.ru: направление — роль и слова названия, грейд — слово в названии, навыки — «Ключевые навыки» → теги справочника (разбору не даются). «Подтверждённые» — кандидаты, у которых грейд подтверждён тестом. Покрытие требований — доля обязательных навыков потребности, подтверждённых тестом (T1), у лучшего из первых пяти.

В репозитории — номера вакансий, ссылки и производные метки (`docs/realdata/hh_match_corpus.json`); тексты вакансий не хранятся (FTT.6: парсинг — только для тестовых данных).

## Добор уровнем выше (match-v1.3): до и после

«До» — тот же код и тот же разбор с `MATCH_GRADE_ABOVE=0` (порядок match-v1.2: только точная категория), «после» — продукт по умолчанию: если в точной категории меньше 30 кандидатов с подтверждённым или предварительным грейдом, подборка добавляет категорию на ступень выше; первые 2 места — лучшие точного уровня, дальше кандидат уровнем выше стоит выше точного, только если покрывает больше обязательного. Добор сработал: 41,9 % (99 из 236) вакансий каталога; доля кандидатов уровнем выше в первых пятёрках — 22,1 % (259 из 1172). На синтетике со скрытой истиной правило не ухудшает P@5, P@10, nDCG@5, nDCG@10 и MRR ни в одном из шести миров — `docs/validation/grade_above.json`.
