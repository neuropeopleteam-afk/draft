# Правило выбора «правила решения v2» на TRAIN (21.10.2026, записано до запуска сетки)

Сетка — `docs/validation/TRAIN_PLAN_2110d.json`: V0 = настройки FINAL №2 (STAND_ENV), V1–V11 — изменения поверх
(δ SPRT, α/β, продление у спорного порога, мин./макс. заданий, classify_z, вес времени, randomesque k = 3).
Зёрна TRAIN 1201–1210 (нигде не использованы), 120 модельных кандидатов на зерно, с повтором (`--retest`) и
фиксированной формой той же длины (`--fixed`). S_* — стандартные условия (S-T мир, как в аналогичных решениях),
T_* — жёсткие. Метрики считает независимый скрипт А15 `a15_recompute.py` (точка «после второго этапа», stage2).
Выбор делает `tools/publish/train_choice_v2.py` — без ручного выбора.

## Ограничения (обязательны в ОБОИХ мирах, в людях)
1. Ложное подтверждение (от всех) k_FC ≤ 0,025 · N.
2. p90 минут всего пути (основная часть + второй этап) ≤ 75.
3. Ошибок движка 0.
4. Утечка: после выбора — боты `cheat_bots` на зерне разработки 3301 (как в FINAL №2) — 0 ложных подтверждений у
   стратегий утечки; если у выбранного не 0 — берётся следующий по правилу.

## Критерий (только мир S-T — там определения совпадают с соперниками)
Для каждой строки сравнения i — запас m_i = x_i − r_i в процентных пунктах (κ и κw × 100; «выше истинного» — r_i − x_i),
r_i — лучший известный соперник (таблица 4.3 хендовера 17 и находка А13 по настоящему финалисту):

| строка | r_i |
|---|---|
| точный грейд, 5 ступеней | 74,5 % |
| точный грейд, 4 ступени | 81 % |
| ±1 ступень, 4 ступени | 99,8 % |
| κ решения при повторе | 0,49 |
| то же решение при повторе | 86 % |
| κw повтора (6 ступеней) | 0,85 |
| κw с истиной, 4 ступени | 0,90 |
| тот же грейд при повторе (6 ступеней) | 75 % |
| тот же грейд при повторе (5 ступеней) | 71,4 % |
| адаптивный − фиксированный той же длины, 4 ступени | +10 п.п. |
| «вдали» от порогов (> 0,25), 4 ступени | 90 % |
| выше истинного, 5 ступеней (меньше — лучше) | 3,3 % |
| верный вердикт вне ±0,3 от порога | 91 % |

Счёт конфигурации — **минимальный запас min_i m_i** (максимин: «выше по всем строкам» упирается в худшую строку).
Выбирается конфигурация с наибольшим счётом среди прошедших ограничения; при разнице ≤ 0,5 п.п. — выше точность
уверенного вердикта (S-T), затем меньше среднее время.

## Когда остаётся №2
Если никто не прошёл ограничения или у выбранной счёт не выше счёта V0 более чем на 0,5 п.п. — FINAL №3 не
замораживается, на сайте остаётся FINAL №2 (сообщение штабу). V0 сам ограничения может не пройти (FINAL №2: в
жёстких FC 2,7 %, p90 81 мин) — тогда сравнение со счётом V0 всё равно делается, а V0 не выбирается.

## Поправка №1 к правилу (замечания А15 P1-1…P1-3, 21.10 ~19:10 — внесена ДО просмотра результатов сетки)
1. **Зёрна FINAL №3 — отдельные фазы** `final3` / `st3` с наборами FINAL3_SEEDS = 4601–4610 и ST3_SEEDS = 5601–5610
   (product_sim): по умолчанию и по проверке набора №3 не может пойти на использованные 4401–4410 / 5501–5510.
2. **«Лучше V0» — парно, с учётом шума.** Для каждой V считается парный бутстрэп по зёрнам (кластер = зерно; у V и V0 те
   же зёрна и те же люди; B = 200, seed 2110): 95 % ДИ разности счёта (максимин) V − V0 и SE счёта V. Среди прошедших
   ограничения берётся лучший по счёту; «ничья» — все в пределах 1 SE лучшего, из них — вариант с меньшим числом изменений
   от V0, затем выше точность уверенного вердикта. Выбранный идёт в FINAL №3, только если **нижняя граница парного 95 % ДИ
   разности с V0 > 0**; иначе остаётся FINAL №2. (Прежние «0,5 п.п.» — отменены: ниже шума.)
3. **Утечка (ограничение 4):** на зерне разработки 3301 ложные подтверждения стратегий утечки — наивной (cheat_bots) и
   рациональной (скрипт А15 a15_leak_rational.py) — не выше контроля (случайные ответы) + 1 случай на 200; иначе берётся
   следующий по правилу.
4. Строка сопоставимости «повтор в определении соперника» (доля общих семейств во второй форме = 36 %, как у него; не
   подбирается) — только справочная, объявляется в протоколе №5 до прогона; основная строка повтора — наша (0 % общих).
Реализация — tools/publish/train_choice_v2.py (`--boot 200`).
