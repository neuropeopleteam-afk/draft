# Что сделано к финалу (19–21.10.2026) и почему

Этап доработки решений перед финальной экспертизой. Изменения выкладывались волнами: после каждой — сборка,
полный прогон тестов, пробный стенд, обход всех ролей. Цифры здесь не приводятся — все значения и условия
измерений в [`docs/NUMBERS.json`](../NUMBERS.json), разделе 5 документации и на странице `/validation`.

## Главная идея доработки

Эксперты оценивают не только результат, но и честность процедуры проверки. Поэтому основное время ушло не на новые
экраны, а на то, чтобы каждая цифра была измерена тем же кодом, что работает на сайте, на данных, которые не
участвовали в настройке, и публиковалась вместе с условиями.

## Волна 1 — кабинеты, демо для жюри, базовые механики

| Что | Почему |
|---|---|
| **Кабинеты кандидата, работодателя и ФСП** перестроены по сценариям: что здесь делать, куда нажать | Критерий «интерфейс»: понятность с первого экрана |
| **Раздел «Демо для жюри»** (`/demo`): вход в любую демо-роль в один клик, у каждого эксперта своя песочница | Эксперт проверяет сценарии сам, не мешая другим и не засоряя рабочую базу |
| **Честность прохождения**: решение принимается по двум и более сигналам или прямому доказательству, автоматической блокировки нет; подозрение — короткая устная защита | Случайный сигнал не должен стоить честному кандидату результата |
| **Официальные протоколы ФСП**: индекс протоколов соревнований ФСП России; кандидат находит свою строку, работодатель видит ссылку на документ | ТЗ не даёт API реестра ФСП; официальные документы — самый надёжный доступный источник |
| **Мобильная версия**: меню телефона, установка как приложение, Android-приложение | ТЗ 3.5: адаптивность и мобильные платформы |
| **«Полигон»**: практические режимы для работодателя и кандидата; голос включается только по явному действию | Практический этап и демонстрация защиты теста |
| **Качество**: исправлены найденные регрессии, все падавшие тесты, проверка секретов в истории | Стабильность перед экспертизой |

## Волна 2а — интерфейс, рыночный режим, документы ФСП

| Что | Почему |
|---|---|
| **Рыночный режим.** Настоящие пользователи (гость, кандидат, работодатель, представитель ФСП) нигде не видят демо-данных и элементов для жюри; пустые состояния честные; всё демо — только в `/demo` | Платформа работает как продукт для рынка, а не как стенд |
| **Понятность**: главная и `/demo` в три шага, под каждым заголовком экрана — одна фраза «что здесь делать», термины — только в подсказках «как считается»; страница методики `/validation` переписана | Жюри и настоящие пользователи без подготовки |
| **Подборки и карточка кандидата**: разряд по ЕВСК и ссылка на PDF протокола, фильтр «только с протоколами ФСП», «учитывать решения компании», слоты собеседования | Объяснимость выдачи и удобство работодателя |
| **Статусы достижений ФСП** и **очередь подтверждений** для представителя федерации; кабинет ФСП — на обезличенных агрегатах | Достижение без документа не должно поднимать кандидата; федерация подтверждает сама |
| **Индекс протоколов ФСП, новая версия**: судьи, тренеры и справки исключены; ключи поиска — HMAC с серверным секретом; разряд по ЕВСК выводится из места, числа субъектов РФ и состава судейской коллегии; обработка сверена с Положением ФСП о персональных данных | 152-ФЗ и точность сведений о спортсменах |
| **Согласия**: отзыв согласия на публикацию закрывает контакты; ключи ATS с ограниченным сроком действия | Контроль кандидата над своими данными |

## Волна 2б — банк, методика, подбор и итоговые цифры

| Что | Почему |
|---|---|
| **Банк заданий**: закрыта утечка позиции правильного ответа; практические задания у порогов грейда; пересмотрены параметры различающей силы; снята с выдачи серия однотипных клонов; грейд убран из условий заданий | Устойчивость к распространению и сопоставимость сложности — проверяются валидатором, а не обещаются |
| **Вердикт теста — тремя исходами**: грейд подтверждён · не подтверждён · у самой границы — короткий дополнительный этап | Угадывать точную ступень у кандидата, чей уровень лежит на границе, нельзя ни одним методом; честнее назначить второй этап |
| **Метод вердикта**: байесовская последовательная классификация с ранней остановкой по последовательному критерию Вальда | Вердикт по вероятности уровня, тест короче, когда ответ уже ясен |
| **Подбор по правилу экспертов**: грейд в выдаче — только подтверждённый тестом; достижения ФСП: «подтверждено» — полный вес, «ждёт подтверждения» — половина, без документа — ноль; без истории ФСП — без штрафа | Требования ТЗ к подбору и честности выдачи |
| **Протоколы до прогонов**: что меряем, на каких данных, как выбираем настройки — коммит в репозитории до отчётного прогона; отложенные наборы заморожены, хэш зафиксирован | Защита от подгонки под результат |
| **Один отчётный прогон** на отложенных данных; настройка — только на обучающих | Нет выбора лучшего из нескольких прогонов |
| **Симуляция продукта**: модельные кандидаты проходят тот же движок, что на сайте, на реальном банке | Цифры описывают продукт, а не упрощённую модель |
| **Две строки рядом**: стандартные условия, принятые в аналогичных решениях, и наша проверка на прочность (угадывание, завышенные заявки, кандидаты у границы, неточные параметры заданий, неточные резюме); заголовок выбран до прогонов | Сопоставимость с другими решениями без потери строгости |
| **Реальные вакансии hh.ru**: новый отложенный набор, один прогон; спорные метки перепроверены независимыми арбитрами-моделями (не людьми — это подписано) | Проверка разбора потребности на живом тексте |
| **Внешний открытый набор вакансий** | Независимая проверка разбора на данных, которых команда не собирала |
| **Убраны цифры, которые нельзя честно подтвердить**, в том числе совпадение грейда по слову в названии вакансии (тавтология) | Каждая опубликованная цифра должна что-то доказывать |
| **README и документация переписаны**; все цифры подставляются из `docs/NUMBERS.json` сборкой `python3 docs/submission/build.py` | Одни и те же значения на сайте, в документации и в презентации |

## Финальная волна (21.10, вечер) — подбор, честный отказ от «улучшений», эксплуатация

| Что | Почему |
|---|---|
| **Подбор, цикл №4**: если кандидатов точного уровня меньше десяти, подтверждённые ступенью ниже идут сразу после них и до кандидатов без подтверждения — с причиной в карточке. Протокол и отложенные миры заморожены до прогона, независимый рецензент дал «ок», прогон — один, результат опубликован при любом исходе | Работодатель не получает пустую выдачу, а порядок «подтверждённое выше неподтверждённого» сохраняется |
| **Отказ от «улучшений», которые не прошли правило**: новые варианты теста (два раунда) и порядка подбора (цикл №5) проверялись только на обучающих данных по правилу выбора, записанному до перебора; ни один не оказался лучше — на сайте остались прежние версии, отложенные данные повторно не использовались | Число нельзя поднять, перебирая варианты на тех же данных, на которых отчитываемся |
| **Подборка**: переключатель «Строго запрошенный грейд» сохраняет новую версию подборки; кандидат уровнем выше запроса помечен «сильнее запроса»; поиск по базе кандидатов ускорен без изменения ответа | Уточнение без потери прежней выдачи и быстрый отклик на живом стенде |
| **Экспресс-тест**: исключены семейства заданий, выпадающие из ряда сложности; служебная строка генератора больше не показывается кандидату и в разборе | Экспресс — короткий, ровный по сложности и понятный |
| **ATS работодателя**: контакты кандидата и время согласия передаются в событии вебхука только после принятия приглашения; до согласия — без контактов (покрыто тестом) | Тот же принцип «контакты — после согласия», что и на сайте |
| **Профиль**: стаж — от 0 до 45 лет и не больше возраста минус 14, с понятной ошибкой в форме | Защита от заведомо неверных анкет |
| **Индекс протоколов ФСП, версия 7**: перед сверкой записан протокол независимого слепого аудита выборки строк | Достижение в карточке опирается на проверенную строку официального протокола |
| **Ответы API методики** — без названий моделей и поставщиков: на экране роли («модель-арбитр А/Б») | Правило продукта — на экранах не называем поставщиков |
| **Эксплуатация на время экспертизы**: ротация журналов всех сервисов (docker-compose), прогрев описания API при старте каждого процесса | Стенд должен стабильно работать все дни экспертизы |
