# Что сделано к финалу (19–21.10.2026) и почему

Этап доработки решений перед финальной экспертизой. Изменения выкладывались волнами: после каждой — сборка,
полный прогон тестов, пробный стенд, обход всех ролей. Цифры здесь не приводятся — все значения и условия
измерений в [`docs/NUMBERS.json`](../NUMBERS.json), разделе 5 документации и на странице `/validation`.

## Главная идея доработки

Эксперты оценивают не только результат, но и честность процедуры проверки. Поэтому основное время ушло не на новые
экраны, а на то, чтобы каждая цифра была измерена тем же кодом, что работает на сайте, на данных, которые не
участвовали в настройке, и публиковалась вместе с условиями.

## Волна 1 — продукт как для рынка

| Что | Почему |
|---|---|
| **Рыночный режим.** Настоящие пользователи (гость, кандидат, работодатель, представитель ФСП) не видят демо-данных и элементов для жюри; всё демо — в разделе «Демо для жюри» (`/demo`), у каждого эксперта своя песочница | Платформа должна работать как продукт для рынка, а не как стенд; эксперт при этом входит в любую роль в один клик |
| **Кабинеты кандидата, работодателя и ФСП** перестроены по сценариям: что здесь делать, куда нажать | Критерий «интерфейс»: понятность с первого экрана |
| **Подбор**: грейд в выдаче — только подтверждённый тестом; без истории ФСП — без штрафа; уточнение фильтров создаёт новую версию подборки | Требования ТЗ к подбору и честности выдачи |
| **Честность прохождения**: решение принимается по двум и более сигналам или прямому доказательству, автоматической блокировки нет; подозрение — короткая устная защита | Случайный сигнал не должен стоить честному кандидату результата |
| **Официальные протоколы ФСП**: индекс протоколов соревнований ФСП России; кандидат находит свою строку, работодатель видит ссылку на документ | ТЗ не даёт API реестра ФСП; официальные документы — самый надёжный доступный источник |
| **Мобильная версия**: меню телефона, установка как приложение, Android-приложение | ТЗ 3.5: адаптивность и мобильные платформы |
| **«Полигон»**: практические режимы для работодателя и кандидата; голос включается только по явному действию | Практический этап и демонстрация защиты теста |
| **Качество**: исправлены найденные регрессии, все падавшие тесты, проверка секретов в истории | Стабильность перед экспертизой |

## Волна 2а — механика и документы ФСП

| Что | Почему |
|---|---|
| **Вердикт теста — тремя исходами**: грейд подтверждён · не подтверждён · у самой границы — короткий дополнительный этап | Угадывать точную ступень у кандидата, чей уровень лежит на границе, нельзя ни одним методом; честнее назначить второй этап |
| **Метод вердикта**: байесовская последовательная классификация с ранней остановкой по последовательному критерию Вальда | Вердикт по вероятности уровня, тест короче, когда ответ уже ясен |
| **Банк заданий**: пересмотрены параметры различающей силы; снята с выдачи серия однотипных клонов; закрыты служебные поля, видимые кандидату; грейд убран из условий заданий | Устойчивость к распространению и сопоставимость сложности — проверяются валидатором, а не обещаются |
| **Статусы достижений ФСП**: «подтверждено ФСП» — полный вес, «ждёт подтверждения» — половина, заявлено без документа — ноль; очередь подтверждений для представителя федерации | Достижение без документа не должно поднимать кандидата |
| **Разряд по ЕВСК** выводится из места, числа участвующих субъектов РФ и состава судейской коллегии, с основанием | Работодателю нужен понятный уровень спортсмена, а не только место |
| **Персональные данные спортсменов**: судьи, тренеры и справки исключены из индекса; ключи поиска — HMAC с серверным секретом; открытого каталога нет; обработка сверена с Положением ФСП | 152-ФЗ и Положение ФСП об обработке персональных данных |
| **Карточка кандидата**: ЕВСК и ссылка на PDF протокола; фильтр «только с протоколами ФСП»; «учитывать решения компании» | Объяснимость выдачи |
| **Согласия**: отзыв согласия на публикацию закрывает контакты; ключи ATS с ограниченным сроком действия | Контроль кандидата над своими данными |
| **Понятность**: под каждым заголовком экрана — одна фраза «что здесь делать»; термины — только в подсказках «как считается» | Жюри и настоящие пользователи без подготовки |

## Волна 2б — итоговые прогоны и цифры

| Что | Почему |
|---|---|
| **Протоколы до прогонов**: что меряем, на каких данных, как выбираем настройки — коммит в репозитории до отчётного прогона; отложенные наборы заморожены, хэш зафиксирован | Защита от подгонки под результат |
| **Один отчётный прогон** на отложенных данных; настройка — только на обучающих | Нет выбора лучшего из нескольких прогонов |
| **Симуляция продукта**: модельные кандидаты проходят тот же движок, что на сайте, на реальном банке | Цифры описывают продукт, а не упрощённую модель |
| **Две строки рядом**: стандартные условия, принятые в аналогичных решениях, и наша проверка на прочность (угадывание, завышенные заявки, кандидаты у границы, неточные параметры заданий, неточные резюме); заголовок выбран до прогонов | Сопоставимость с другими решениями без потери строгости |
| **Реальные вакансии hh.ru**: новый отложенный набор, один прогон; спорные метки перепроверены независимыми арбитрами-моделями (не людьми — это подписано) | Проверка разбора потребности на живом тексте |
| **Внешний открытый набор вакансий** | Независимая проверка разбора на данных, которых команда не собирала |
| **Убраны цифры, которые нельзя честно подтвердить**, в том числе совпадение грейда по слову в названии вакансии (тавтология) | Каждая опубликованная цифра должна что-то доказывать |
| **README и документация переписаны**; все цифры подставляются из `docs/NUMBERS.json` сборкой `python3 docs/submission/build.py` | Одни и те же значения на сайте, в документации и в презентации |
