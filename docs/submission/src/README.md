# «Драфт» — найм IT-специалистов с подтверждённым грейдом

«Драфт» — платформа подбора, где механика найма развёрнута в обратную сторону: кандидат один раз проходит проверку
навыков и получает подтверждённую категорию «направление · грейд», а работодатель сам выходит на кандидата
с приглашением, в котором обязательно указана зарплатная вилка. Достижения кандидата в соревнованиях Федерации
спортивного программирования (ФСП) подтверждаются по официальным протоколам федерации и дают бонус в подборке;
кандидат без истории ФСП не теряет ничего.

Решение подготовлено командой Neuropeople для специального трека ФСП (Лидеры цифровой трансформации 2026).
Оператор платформы — команда Neuropeople.

## Что умеет платформа

**Кандидат** регистрируется по почте с подтверждением, отвечает на короткий опрос (направление, стек), выбирает
грейд, на который претендует, и проходит адаптивный тест. Итог — один из трёх ответов: грейд подтверждён, не
подтверждён, или нужен короткий дополнительный этап. Подтверждённая категория появляется в профиле вместе с
объяснением, на каких заданиях она получена. Кандидат управляет тем, что видят компании, получает приглашения,
принимает или отклоняет их и в любой момент может выгрузить или удалить свои данные.

**Работодатель** описывает задачу своими словами или загружает файл вакансии. Платформа выделяет требования
(направление, грейд, стек) с цитатами из текста, убирает дискриминирующие условия и строит подборку обезличенных
кандидатов с объяснением «почему этот кандидат здесь». Приглашение отправляется только с зарплатной вилкой;
контакты кандидата раскрываются после его согласия. Есть сравнение кандидатов, статусы найма, передача в
системы учёта кандидатов (ATS) и задания для кандидатов с автопроверкой.

**Федерация ФСП** видит кадровый резерв по регионам и направлениям в сравнении со спросом рынка, подтверждает
достижения спортсменов и ведёт трёхстороннюю связь «компания — кандидат — ФСП».

**Эксперты жюри** входят в любую демо-роль в один клик в разделе «Демо для жюри» (`/demo`). Основной сайт работает
как рыночный продукт: настоящие пользователи не видят демо-данных.

## Как устроена проверка и подбор — коротко

1. **Тест.** Банк из {{bank_families}} параметрических семейств заданий по {{bank_directions}} направлениям: каждый
   кандидат получает свои варианты, поэтому утечка конкретных заданий не помогает. Тест адаптивный: следующее
   задание подбирается по уже данным ответам, а у границы грейда тест задаёт уточняющие вопросы.
2. **Вердикт.** Платформа отвечает на вопрос работодателя «подтверждён ли заявленный грейд» — тремя исходами, а
   у границы назначает короткий второй этап вместо угадывания.
3. **Честность прохождения.** Сигналы (переключение вкладок, вставка текста, нетипичное время и др.) не банят
   автоматически: при двух и более сигналах кандидату предлагается короткая устная защита решения.
4. **ФСП.** Достижения сверяются с официальными протоколами ФСП России: статус «подтверждено ФСП» даёт полный бонус,
   «ждёт подтверждения» — половину, заявленное без документа — ноль. Отсутствие истории ФСП не штрафуется.
5. **Подбор.** Грейд в подборке учитывается только подтверждённый тестом. Кандидаты ранжируются по совпадению
   навыков, подтверждённому грейду и фактам ФСП, у каждого — объяснение. Фильтры работодателя не теряют прежнюю
   подборку: каждое уточнение создаёт новую версию.

## Правила, которые важны кандидату

- Неудачная попытка **не понижает** подтверждённый грейд.
- После неподтверждённой попытки тест на **грейд ниже** — сразу, на **тот же или выше** — не раньше чем через
  {{repo.retake_same_grade_days}} дней. Сменить подтверждённый грейд можно не чаще раза в {{repo.grade_change_interval_days}} дней.
- **Без истории ФСП** кандидат остаётся в выдаче на общих основаниях: составляющая ФСП у него равна нулю, без штрафа.

Значения берутся из кода (`backend/app/core/config.py`, правила — `backend/app/modules/assessment/rules.py`).

## Что видно до согласия кандидата

- Работодатель видит **обезличенную карточку**: подтверждённый грейд, навыки с заданиями-доказательствами, факты ФСП
  со статусом, объяснение «почему в подборке». Имени и контактов нет; кандидат сам выбирает, какие поля карточки
  показывать, и без согласия на публикацию не виден вовсе.
- В приглашении **обязательна зарплатная вилка** «от–до» в рублях (проверяется и в базе данных), название компании,
  описание предложения и способ связи — кандидат видит условия до начала общения.
- **Контакты открываются** только после принятия приглашения или собственного отклика кандидата. Кандидат может
  **отозвать** доступ к контактам и согласие на публикацию в любой момент — контакты снова закрываются.

## Честные цифры

Все значения подставлены из [`docs/NUMBERS.json`](docs/NUMBERS.json) — единого файла цифр, который собирается из
отчётов прогонов командой `python3 tools/publish/gen_numbers.py`. У каждой цифры — на ком измерено, объём выборки,
дата и команда пересчёта. Модельные расчёты подписаны «модельные кандидаты, не люди».

Каждая метрика показана дважды и рядом: в **стандартных условиях**, принятых в аналогичных решениях, и в **проверке
на прочность** — наших жёстких условиях (угадывание, завышенные заявки, кандидаты у самой границы грейда, неточные
параметры заданий, неточные резюме). Какие условия идут заголовком, решено до прогонов и от результатов не зависит.

## Как запустить

Нужны Docker с Compose v2.24+ и `make`.

```bash
git clone https://github.com/neuropeopleteam-afk/draft.git && cd draft
make up          # .env со случайными секретами, сборка, миграции, демо-данные
# сайт: http://localhost:8080, API: http://localhost:8080/api/docs
make logs        # в режиме разработки здесь видны коды подтверждения почты
make test        # тесты backend в контейнере
make down        # остановить (данные БД сохраняются)
```

Без Docker: `make dev-backend` (SQLite, автоперезагрузка) и `make dev-frontend` (Vite, прокси `/api`). Без ключа
внешней языковой модели платформа работает полностью: разбор текста и проверка развёрнутых ответов переходят на
правила и очередь ручной проверки (`LLM_DISABLED=true`). Все переменные окружения описаны в `.env.example`.
Подробная инструкция по сборке и развёртыванию — раздел 9 документации.

## Ограничения — честно

- Точность теста и подбора измерена на модельных кандидатах и реальных вакансиях; калибровки заданий на большой
  выборке живых людей пока нет — это следующий шаг после запуска.
- Боевая интеграция с реестром ФСП требует API федерации; сейчас достижения сверяются с опубликованными
  официальными протоколами, а вход через «ФСП ID» показан на демо-стенде.
