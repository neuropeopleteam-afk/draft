# Внешние интеграции

Сводка: что платформа берёт из внешних систем и где подробности.

| Система | Что берём / отдаём | Документ |
|---|---|---|
| Реестр ФСП | рейтинг и подтверждённые участия (T2) | [FSP_INTEGRATION.md](FSP_INTEGRATION.md) |
| ATS (Talantix, «Поток», Хантфлоу, вебхук) | профиль кандидата → ATS, этапы ← ATS, импорт вакансий из «Потока» | [ATS.md](ATS.md) |

Все интеграции за флагами и выключены по умолчанию; без ключей функция скрыта, а не сломана.

## hh.ru

Модуль `backend/app/modules/hh` (Я12). Интерфейс: кнопка «Импортировать с hh.ru» в «Вакансиях» работодателя рядом
с «Импортировать из ATS», строка «Рынок по hh.ru» под вилкой в форме приглашения, блок «Разбор потребности на
вакансиях hh.ru» на /validation.

### Что берём

1. **Импорт своей вакансии** (как синхронизация из ATS, FTT.5). Работодатель вставляет ссылку
   (`https://hh.ru/vacancy/123`, `…/vacancy/123?from=…`, `hh.ru/vacancy/123`) или номер. Платформа читает
   `GET /vacancies/{id}` и берёт: название, описание (HTML → текст), `key_skills`, опыт, график/формат/занятость,
   зарплату, город. Текст с ключевыми навыками проходит **тот же разбор потребности** (`need_parser.parse_need`, путь
   правил без LLM — как у импорта из «Потока»): направление, грейд, стек, опыт. Дальше:
   * всегда **черновик** вакансии (`status=draft`) с источником «с hh.ru · № …», ссылкой на hh.ru и датой импорта
     (`updated_at` вакансии на hh.ru); публикует работодатель сам после проверки;
   * стек = навыки из текста ∪ `key_skills`, сопоставленные со справочником стека;
   * вилка — из hh.ru, если она в рублях, за месяц и ширина «до/от» ≤ 1,5 (основание — `gross` из hh.ru: до вычета
     НДФЛ или на руки); только «от» или «до» — вторая граница достраивается (× 1,25 / ÷ 1,25), шире 1,5 — «до»
     обрезается до 1,5 × «от», в обоих случаях пометка «уточните»; нет суммы или не рубли за месяц — рыночный
     диапазон категории (на руки) с пометкой. На корпусе 193 вакансий: целиком из hh.ru — 10 %, частично — 33 %
     (у остальных зарплата не указана или не в рублях за месяц), см. `docs/validation/HH_PARSE.md`;
   * формат — из `work_format` hh.ru (REMOTE / ON_SITE / HYBRID); город — из `area`;
   * в конец описания — строка «Условия с hh.ru — опыт · график · формат · занятость», чтобы ничего не потерялось;
   * повторный импорт: «без изменений» / «изменилась на hh.ru» (обновит черновик) / «изменена на платформе» (не
     перезаписывает правки работодателя) — те же правила, что у «Потока» (ATS.md §12).
2. **Рынок по hh.ru** — медиана и 25–75-й перцентиль вилок живых вакансий роли, грейда и региона рядом с вилкой
   приглашения. Только агрегат: n, дата, регион, ступень поиска, доля сумм «до вычета», ссылка на тот же поиск на
   hh.ru для самопроверки.
3. **Корпус для проверки разбора** (`tools/realdata/hh_corpus.py`) — 150–200 реальных ИТ-вакансий; в репозитории
   только номера, ссылки и производные метки (`docs/realdata/hh_corpus.json`), числа — `docs/validation/HH_PARSE.md`.

### Почему не витрина вакансий

Ответ организаторов FTT.6: поиск и показ **чужих** вакансий hh.ru — не продуктовая механика спецтрека, парсинг
допустим только для тестовых данных. Поэтому:

* поиска вакансий hh.ru в интерфейсе нет; импорт — одна вакансия по ссылке/номеру;
* импорт — только своей вакансии: если работодатель в hh.ru не совпадает с названием компании на платформе,
  импорт требует явного подтверждения «Это вакансия нашей компании» (иначе 409 `hh_confirm_own`); проверка мягкая
  (по названию), потому что API с токеном приложения не знает, чей это аккаунт работодателя;
* «Рынок по hh.ru» отдаёт только агрегат, список вакансий наружу не уходит;
* корпус — без текстов вакансий в репозитории.

### Как считается «Рынок по hh.ru»

* Поиск `GET /vacancies` с `only_with_salary=true`, `per_page=100`: профессиональная роль hh.ru (Backend/Frontend —
  «Программист, разработчик» 96 + слова в названии; QA — 124; Data/ML — 165 и 96 со словами; ИБ — 116) и грейд.
* Ступени, первая с n ≥ 20: регион + слово грейда в названии → регион + опыт hh.ru (приближение грейда) → Россия +
  слово грейда → Россия + опыт. Если ни одна не дала 20 — берётся ступень с наибольшим n и пометка «мало данных,
  ориентир неустойчивый»; меньше 8 вакансий — чисел нет, только «мало данных». Удалённая вакансия — по всей России.
* Значение вакансии: середина вилки, если есть «от» и «до»; иначе «от» или «до». Только рубли и оплата за месяц
  (остальное не считается, число исключённых — в ответе); выбросы вне 10 тыс. – 3 млн ₽ отброшены.
* Суммы с `gross=true` переводятся «на руки» по шкале НДФЛ 13–22 % (`contact/salary.py`), как рыночный диапазон
  Хабр Карьеры у категории ([SALARY_SOURCES.md](SALARY_SOURCES.md)); рядом — медиана ≈ до вычета. Доля сумм «до
  вычета» в выборке — в ответе и в подписи «Как считали».
* Честно: это **вилки в объявлениях работодателей**, не фактические зарплаты; грейд по слову в названии и по опыту —
  приближение.
* Контекст: из своей потребности (`need_id`: категория, город, удалёнка) или из категории кандидата (`ref`), город —
  город потребности, иначе компании.

### Ограничения и бережность к API

* Токен приложения (`HH_APP_TOKEN`) и `HH_USER_AGENT` — из `secrets/hh.env` (на сервере
  `/opt/spectrek_fsp/secrets/hh.env`). Заголовки: `Authorization: Bearer`, `HH-User-Agent` и `User-Agent`.
  `client_id`/`client_secret` платформе не нужны: повторный запрос токена приложения отзывает действующий.
* Не чаще 1 запроса в секунду на весь сервер (файловая блокировка `fcntl` на все процессы uvicorn); дольше 30 с в
  очереди — ответ 503 `hh_busy` («повторите»).
* Кэш на диске (`HH_CACHE_DIR`, по умолчанию `/tmp/hh_cache`): вакансия — 10 мин, поиск для рынка — 24 ч. Если
  hh.ru не отвечает, отдаём прошлые данные с пометкой «hh.ru сейчас не отвечает — показаны прошлые данные».
* Ошибки — понятные: 404 `hh_not_found` («вакансия не найдена или снята»), 422 `hh_bad_ref` / `hh_bad_request`,
  429 `hh_rate_limited`, 401/403 → 502 `hh_forbidden` (токен), капча → 502 `hh_captcha`, 5xx → 502
  `hh_unavailable`, тайм-аут (10 с) → 504 `hh_timeout`. Выключено — 404 `hh_disabled`, кнопок нет.
* Архивная вакансия импортируется с пометкой «в hh.ru вакансия в архиве — проверьте, актуальна ли она».

### Флаги и режимы

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `HH_ENABLED` | `false` | включить интеграцию (кнопка, рынок, блок /validation) |
| `HH_APP_TOKEN`, `HH_USER_AGENT` | — | из `secrets/hh.env`; без них функция скрыта даже при `HH_ENABLED=true` |
| `HH_STUB` | `false` | заглушка с фикстурами (`modules/hh/fixtures/vacancies.json`, синтетический рынок) — тесты, CI, e2e; в интерфейсе плашка «заглушка, данные не настоящие» |
| `HH_CACHE_DIR` | `/tmp/hh_cache` | каталог кэша ответов |
| `HH_TIMEOUT_S`, `HH_MIN_INTERVAL_S` | `10`, `1.0` | тайм-аут и минимальный интервал между запросами |
| `HH_VACANCY_TTL_S`, `HH_MARKET_TTL_S` | `600`, `86400` | кэш вакансии и поиска |

`/api/meta` → `hh: {enabled, stub}`; фронтенд показывает кнопки только при `enabled`.

docker-compose: `env_file: ${HH_ENV_FILE:-./secrets/hh.env}` с `required: false` — без файла сервис стартует.
Миграций нет: используются поля вакансии `source='hh'`, `external_id`, `external_url`, `imported_at`.

### API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/employer/vacancies/import/hh/preview?ref=` | `HhPreviewOut`: что попадёт в черновик, состояние повторного импорта, нужен ли флажок «своя» |
| POST | `/api/employer/vacancies/import/hh` `{ref, confirm_own}` | `HhImportOut`: `created` / `updated` / `skipped` + `vacancy_id` |
| GET | `/api/employer/market/hh?need_id=&ref=&category_id=&city=` | `HhMarketOut`: медиана, p25, p75 (на руки), n, дата, ступень, пометки |
| GET | `/api/validation/hh-parse` | `HhParseOut`: замер разбора на корпусе hh.ru |

Модели ответов — в OpenAPI (`/api/docs`, тег «hh.ru»).

### Демо и проверка

`HH_ENABLED=1 HH_STUB=1` — заглушка: вакансии 90000001 (Middle Python, «Северный платёж» — совпадает с демо-компанией
жюри), 90000002 (Junior QA, «опыт не требуется», «удалёнка не предусмотрена»), 90000003 (другая компания — нужен
флажок «своя»), 90000429 — ответ «слишком много запросов». Тесты: `backend/tests/test_hh.py`; e2e:
`e2e/tests/15-hh-import.spec.ts` (1440 и 390, axe).
