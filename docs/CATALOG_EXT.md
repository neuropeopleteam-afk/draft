# Каталог шире: 4 новых направления

К пяти направлениям (Backend, Frontend, Data/ML, QA, Информационная безопасность) добавлены:

| id | Направление | Чем отличается от ближайшего базового |
|---|---|---|
| `devops` | DevOps / SRE | инфраструктура как код, Kubernetes, CI/CD, мониторинг и алерты, SLO и инциденты, сети |
| `data_eng` | Инженер данных | ETL/ELT-конвейеры, DWH и моделирование данных, dbt, Spark, Airflow, потоковая обработка, качество данных |
| `mobile` | Мобильная разработка | Android (Kotlin, Jetpack Compose), iOS (Swift, SwiftUI), Flutter, React Native, архитектура приложения |
| `analyst` | Системный / бизнес-аналитик | требования, BPMN, UML, user story и критерии приёмки, проектирование интеграций и API, ER-модель |

Всё за флагом **`CATALOG_EXT_ENABLED`** (по умолчанию выключен). Без флага платформа работает ровно как с пятью
направлениями: строки справочника (миграция `ce01`) лежат в БД, но API, опрос, разбор потребности и подбор их не видят.

## Когда направление видно

Правило организаторов FTT.4: уровень присваивается только по тесту. Поэтому направление расширения показывается,
только если одновременно:

1. включён `CATALOG_EXT_ENABLED`;
2. банк заданий направления прошёл проверку — направление есть в `directions_verified` манифеста
   `backend/assessment_bank/BANK_SYNC.json` (пишет `tools/sync_bank.py` после фильтра качества и валидатора банка),
   и то же правило выполняется на загруженном реестре семейств: не меньше 18 семейств без канареек
   (`CATALOG_EXT_MIN_FAMILIES`) и каждый уровень Стажёр…Senior покрыт не меньше чем 3 семействами
   (`CATALOG_EXT_MIN_PER_GRADE`);
3. направление не исключено списком `CATALOG_EXT_DIRECTIONS` (пусто — все готовые).

Состояние — в `/api/meta` → `catalog`: `directions` (все видимые), `ext` (видимые новые), `ext_enabled`.

## Что меняется с флагом

- **Справочник и API.** `/api/catalog` и `/api/catalog/stack-tags` отдают новые направления, 16 категорий и 28 стек-тегов;
  у нового направления в опросе — свои теги, затем связанные теги других направлений (инженеру данных — Spark, Airflow,
  Kafka, ClickHouse…), затем общий блок. Параметр `direction` во всех методах принимает 9 значений; скрытое направление —
  ошибка 422, как прежде любое неизвестное.
- **Опрос и тест.** Новое направление можно выбрать основным или дополнительным; тест — адаптивный из банка
  направления (тот же движок, общий блок + блок направления). Навыки семейств сводятся к стек-тегам каталога
  (`app/modules/assessment/skill_map.py`); Docker у DevOps / SRE и Kafka у инженера данных выдаются всем кандидатам
  направления (ядро профессии, а не выбор стека).
- **Разбор потребности.** Синонимы новых тегов (Terraform, Ansible, Helm, Prometheus и Grafana, dbt, Greenplum, DWH, ETL,
  Jetpack Compose, SwiftUI, Flutter, React Native, BPMN, UML, user story…) распознаются; вакансии «DevOps-инженер», «SRE»,
  «Data Engineer / инженер данных», «Android/iOS-разработчик», «системный / бизнес-аналитик» получают своё направление
  вместо «ближайшей категории» с пометкой о частичном соответствии. «Аналитик данных» и «продуктовый аналитик» остаются
  в Data/ML. «React Native» не засчитывается как React. Слово «SPA» засчитывается Frontend только отдельным словом
  (без флага — как подстрока, поэтому «Data Engineer… Spark» уходил во Frontend).
- **Демо.** `python -m app.modules.demo.seed` добавляет модельных кандидатов новых направлений (по 20 на направление:
  4 стажёра, 6 Junior, 6 Middle, 4 Senior; номера 501–580) и по одной демо-потребности — с подписью
  «модель, не люди». Без флага ничего не добавляется.
- **Рынок.** Вилки категорий — калькулятор зарплат Хабр Карьеры на 10.10.2026 (docs/SALARY_SOURCES.md).

## Проверки

- `backend/tests/test_catalog_ext.py` — без флага всё как прежде; флаг без готового банка — направления скрыты; правило
  готовности; 9 направлений и 36 категорий; разбор вакансий новых направлений; опрос в новом направлении.
- Повтор пути по новым направлениям: `make path-retest-ext DIRS=devops,mobile` (то же — `cd backend &&
  CATALOG_EXT_ENABLED=1 python -m app.modules.validation.path_retest --directions devops,mobile`) → `backend/app/modules/validation/data/path_retest_ext.json`,
  `docs/validation/TEST_RETEST_EXT.md` (основной отчёт повтора не меняется).
- Калибровка новых семейств: до прогона панели — априорная трудность (`prior_difficulty`, «априорная трудность»
  в отчётах банка); после прогона — по `bank/calibration/README.md`.

## Включение на стенде

1. Банк новых направлений синхронизирован (`python3 tools/sync_bank.py`; валидатор банка можно прогнать на сервере
   проверок и передать готовый отчёт: `--validation-report <validation_report.json>`), в `BANK_SYNC.json` есть
   `directions_verified`.
2. Миграции применены (`alembic upgrade head` — `ce01` идемпотентна).
3. `CATALOG_EXT_ENABLED=1` в `.env`, перезапуск api.
4. По желанию — модельные кандидаты: `python -m app.modules.demo.seed`.
