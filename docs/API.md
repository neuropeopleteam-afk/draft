# API платформы «Встречный»: обзор

Все методы описаны спецификацией OpenAPI 3.1 (ТЗ, п. 3.5: запросы, ответы, коды ошибок). Подробности по каждому методу — в самой спецификации; здесь только то, что нужно, чтобы в неё войти.

| Где | Что |
|---|---|
| [`docs/api/openapi.json`](api/openapi.json) | Спецификация в репозитории (318 операций): читается без запуска сервера, импортируется в Postman, Insomnia, генераторы клиентов |
| https://fsp.neuropeople.pro/api/docs | Swagger UI стенда: можно выполнять запросы (кнопка Authorize); ReDoc — `/api/redoc`; та же схема — `/api/openapi.json` |
| `http://127.0.0.1:8140/api/docs` | То же при локальном запуске (`make up`) |

Файл в репозитории всегда совпадает со схемой приложения: это проверяет тест `backend/tests/test_openapi_file.py`. После правки API — `make openapi` (пересобрать файл) и закоммитить его.

## Группы методов

Метод относится к одной группе (тег); в Swagger UI они свёрнуты по тегам. Каждый метод содержит: краткое название, описание, строку «Доступ» (нужен ли вход и какая роль), схему запроса, схему и пример успешного ответа, коды ошибок с машинными кодами `detail.code`.

| Тег | Что внутри |
|---|---|
| `auth` | Регистрация, подтверждение почты, вход (JWT), второй фактор (TOTP) |
| `profiles`, `candidate`, `my-data` | Профиль, опрос, согласия 152-ФЗ, приватность, резюме, «Мои данные» (выгрузка, удаление) |
| `assessment`, `proctor` | Тест на грейд (адаптивный), экран «Категория и грейд», камера во время теста по согласию |
| `employer`, `mutual`, `employer-contact` | Потребности работодателя, подборки с версиями, карточки кандидатов, взаимный подбор, приглашения и зонды |
| `candidate-contact`, `contact`, `hiring` | Входящие приглашения и зонды, переписка, встречные предложения, найм после принятия |
| `catalog`, `legal`, `system` | Справочники, тексты согласий и реквизиты оператора, `/api/health`, `/api/meta` |
| `jury`, `jury-live`, `study` | Режим жюри: вход в один клик, песочница с демо-данными, живая демонстрация по QR, статистика прохождения |
| `validation`, `sus`, `expert`, `expert-panel` | Публичные метрики качества, юзабилити SUS, экспертная проверка ответов и разметка |
| `passport`, `fsp-id`, `fsp-registry`, `fsp-cabinet` | Подписанный паспорт грейда, вход через ФСП ID, контракт реестра ФСП, кабинет ФСП (агрегаты) |
| `vacancies`, `cups`, `assignments`, `subscriptions`, `employer-trust` | Вакансии и отклики, «Кубок работодателя», задания с автопроверкой, подписки на потребности, проверка работодателя |
| `ats`, `ats-stub` | Передача кандидатов в ATS (Хантфлоу, Talantix, «Поток») и демо-заглушки этих систем |
| `push` | Web Push для PWA |

## Авторизация

Токен — JWT; передаётся в заголовке `Authorization: Bearer <токен>`.

1. `POST /api/auth/register` — регистрация (роль `candidate` или `employer`, согласие `consent_processing`); на почту приходит шестизначный код.
2. `POST /api/auth/verify-email` — подтверждение кода; в ответе сразу `access_token`.
3. Повторный вход: `POST /api/auth/login` (JSON: `email`, `password`) или `POST /api/auth/token` (форма OAuth2 — для кнопки Authorize в Swagger UI).
4. Если у учётной записи включён второй фактор (TOTP), вход возвращает `second_factor_required` и промежуточный `pending_token`; код из приложения (или резервный) отправляется в `POST /api/auth/2fa/verify` — в ответе токен доступа. Форма `/api/auth/token` для таких учётных записей отвечает 403 `second_factor_required`: пользуйтесь `/api/auth/login`.

Роли: `candidate`, `employer`, `expert`, `fsp_analyst`, `admin`. Требуемая роль указана в строке «Доступ» каждого метода; публичные методы (`/api/health`, `/api/meta`, справочники, проверка паспорта) входа не требуют. Запрос чужого объекта возвращает 404, а не 403, чтобы не раскрывать, что объект существует.

```bash
curl -s https://fsp.neuropeople.pro/api/employer/needs -H "Authorization: Bearer $TOKEN"
```

Стенд закрыт базовой авторизацией nginx; реквизиты — в материалах сдачи. Жюри и эксперты могут получить токен без пароля: `POST /api/jury/login` (демо-персона, своя песочница с данными).

## Формат ошибок

Предметные ошибки платформы:

```json
{"detail": {"code": "invitation_cooldown", "message": "Этому кандидату уже отправляли приглашение за последние 30 дней."}}
```

`code` — стабильный машинный код (для клиента), `message` — текст по-русски (для человека). Ошибка проверки полей запроса (422, формирует FastAPI) — список: `{"detail": [{"loc": ["body", "email"], "msg": "…", "type": "…"}]}`.

| Код | Когда | Где описан |
|---|---|---|
| 400 | Неверный или просроченный код, некорректный запрос | у метода, с машинными кодами |
| 401 | Нет токена или он недействителен | общий ответ `Unauthorized` |
| 403 | Не та роль, почта не подтверждена, учётная запись заблокирована | общий ответ `Forbidden` + коды у метода |
| 404 | Объект не найден или принадлежит другому пользователю | у метода |
| 409 | Конфликт с состоянием: правило 90 дней, пауза между приглашениями, приглашение уже закрыто | у метода, с машинными кодами |
| 413, 422 | Слишком большой файл; ошибка проверки полей или нарушено правило предметной области | у метода |
| 429 | Превышен лимит частоты (вход, коды, проверки паспорта) | у метода |
| 503 | Внешняя система недоступна (реестр, ATS, ФНС), демо-учётки ещё создаются | у метода |

Коды ошибок выводятся из кода обработчиков автоматически (`backend/app/core/api_docs.py`), поэтому не расходятся с реализацией: тест `backend/tests/test_openapi_runtime.py` делает реальные запросы всеми ролями и проверяет, что каждый полученный код ответа и `detail.code` есть в спецификации.

## Примеры и модели ответов

- Примеры запросов и ответов у 192 методов сняты с настоящих ответов приложения на демо-данных (сокращены: списки — до двух элементов, длинные строки обрезаны; токены и почты вычищены). Пересъёмка: `make openapi-examples`, затем `make openapi`.
- Успешный ответ каждого метода описан: модель с полями и типами (305 методов), файл с типом содержимого (9) или пустой ответ (4). Модели лежат в `backend/app/core/api_models*.py` (ключевой жюри-поток, работа с заданиями и кубками, найм, интеграции с ATS и паспорт, кабинет кандидата, валидация и кабинет ФСП); они только описывают ответ — поведение API не меняют. Тест `backend/tests/test_openapi_models.py` сверяет модели с реальными ответами и не даёт числу описанных ответов снижаться. Вложенные объекты со свободной формой (например, подробные отчёты валидации) описаны как объект без фиксированных полей.
- Файловые ответы (выгрузки JSON и CSV, QR, PDF-профиль) описаны с типом содержимого (`application/pdf`, `text/csv`, `image/svg+xml`, …).

## Как проверить полноту

```bash
make openapi          # пересобрать docs/api/openapi.json
make openapi-audit    # таблица: у каких методов нет описания, модели ответа, ошибок, примера
cd backend && python -m pytest tests/test_openapi_file.py tests/test_openapi_models.py tests/test_openapi_runtime.py
```

Название в заголовке спецификации («Спецтрек ФСП — API платформы подбора») временное: итоговое название продукта владелец ещё не утвердил.
