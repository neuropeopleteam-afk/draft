# Добор ступенью выше при малом пуле точного уровня (Я12б, 11.10, match-v1.3)

Код — `backend/app/modules/matching/grade_above.py`, подборка — `ranking.build_selection` / `selection_order(above_id=…)`,
бенчмарк — `matching_bench.platform_orders(above=…)` и `tools/realdata/grade_above_bench.py` (`make grade-above` →
`docs/validation/grade_above.json`), реальные вакансии — `tools/realdata/hh_plus.py match` (`docs/validation/HH_MATCH.md`,
раздел «Добор уровнем выше»). Флаг `MATCH_GRADE_ABOVE` (по умолчанию «1»; «0» — прежний порядок match-v1.2).

## Зачем
На 414 реальных вакансиях hh.ru (тексты реальные, кандидаты — модельные: модель, не люди) лучший из первых пяти
покрывал 36,6 % обязательных навыков вакансии (код `cf391af`). Разбор показал, что дело не в порядке: подборка брала
только точную категорию (направление · уровень), в демо-пуле это в среднем 16 кандидатов с подтверждённым грейдом, и
лучший из пяти уже набирал 36,8 % при потолке пула 37,3 % (лучший кандидат во всей точной категории). Перестановки
внутри категории давали +0,1 п.п. Не хватало самих кандидатов.

## Как устроено (без LLM, веса и балл match-v1 не меняются)
1. Правило действует, если у потребности есть уровень, работодатель не выбирал категории сам и в точной категории
   меньше 30 кандидатов с подтверждённым или предварительным грейдом (`MIN_EXACT`).
2. В пул добавляется категория **на ступень выше** (Middle → Senior, Стажёр → Junior). Ступень ниже не добавляется:
   по правилам истины бенчмарка (`bench_world.true_relevance`) кандидат уровнем выше «может выполнять работу этого
   уровня», уровнем ниже — нет. Кандидаты без подтверждённого грейда — по-прежнему только точной категории.
3. Первые 2 места (`KEEP`) — лучшие кандидаты точного уровня по прежнему порядку.
4. Дальше — прежний порядок по общему пулу (статус грейда → ядро роли → ярус обязательного → балл), и при равном
   ярусе обязательного точный уровень идёт раньше: кандидат уровнем выше стоит выше точного, только если покрывает
   больше обязательных навыков.
5. Объяснение: в карточке — «грейд на ступень выше запрошенного»; над подборкой — «Добор уровнем выше: в категории …
   N кандидатов — меньше 30 …»; в фильтре категорий отмечена и категория выше (снять галочку — только точный уровень).

## Замер на синтетике со скрытой истиной (правило «не хуже»)
`docs/validation/grade_above.json`, «до» — match-v1.2, «после» — match-v1.3, те же миры и компоненты, веса не подбирались.

| Мир | Правило сработало | P@5 до → после | nDCG@10 до → после | MRR до → после |
|---|---|---|---|---|
| 200 × 500, seed 20261006 | 114 из 200 | 0,709 → 0,712 | 0,579 → 0,592 | 0,860 → 0,861 |
| 200 × 500, seed 20261007 | 105 из 200 | 0,717 → 0,720 | 0,572 → 0,583 | 0,860 → 0,861 |
| 50 × 500 (мир ranking_guard) | 29 из 50 | 0,716 → 0,724 | 0,580 → 0,597 | 0,848 → 0,848 |
| 60 × 600 (анализ чувствительности) | 30 из 60 | 0,733 → 0,737 | 0,578 → 0,588 | 0,857 → 0,857 |
| 200 × 2000, основной (оба seed) | 0 | 0,776 / 0,749 — без изменений | 0,573 / 0,552 — без изменений | 0,888 / 0,863 — без изменений |

P@10 и nDCG@5 тоже не ниже во всех мирах. 95 % доверительный интервал разницы nDCG@10 во всех четырёх малых мирах
выше нуля (нижняя граница +0,001…+0,006), для P@5 и MRR включает ноль. В основном мире (около 100 кандидатов на категорию) правило не включается.

Анализ чувствительности основного бенчмарка (`make bench`, миры 60 × 600 — правило включается примерно в половине
потребностей): nDCG@10 платформы выше прежнего в 8 вариантах из 9 (+0,008…+0,013), P@5 — в тех же 8; хуже — вариант
«строгая истина: только точный грейд» (P@5 0,377 → 0,363, nDCG@10 0,413 → 0,407, MRR 0,582 → 0,578): если работодателю
нужен строго точный уровень, кандидаты уровнем выше для него нерелевантны — для этого галочку категории выше снимают.
MRR в двух вариантах с 40 % «раздутых» резюме — −0,001 (0,811 → 0,810), в остальных не ниже.

Отвергнутые варианты (тот же бенчмарк): добор всегда, без порога 30, — P@5 основного мира 0,776 → 0,768…0,772 (в
зависимости от числа мест точного уровня); общий пул только по баллу, без яруса обязательного, — MRR второго малого
мира 0,860 → 0,788.
