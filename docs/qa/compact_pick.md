# Компактная подборка: первый экран за 10 секунд и потребности вне каталога (поток Я10, ветка feat/compact-pick)

Цель — чтобы работодатель (и жюри за 10–15 минут) с первого экрана подборки видел, кого пригласить и почему, а
доказательства открывал по желанию. Порядок выдачи и баллы **не менялись** (match-v1; изменение порядка — поток Я1,
за флагом): правки касаются только раскладки экрана и подписей, а блок «проверено тестом / НЕ проверено» считается из
требований версии.

Замеры и снимки «было / стало» (`metrics.json`, `*_screen.png`, `*_first_card.png`) и скрипт съёмки `shots.mjs` хранятся
вне репозитория (локальный стенд, одна база, та же потребность до и после); числа ниже — из этих замеров.

|---|---|

| «Сравнить выбранных», зонд, задание — над списком | Под карточками; пока кто-то отмечен, панель прилипает к низу экрана |

Компактная карточка (`components/CompactCard.tsx`) — из того же ответа подборки, без новых запросов:

- шапка: №, обезличенный кандидат, категория и состояние грейда, балл и «обязательное: N из M»;
- **Совпало** — навыки потребности, подтверждённые тестом (T1);
- **Не проверено** — по состоянию: «только заявлен(ы)» (T0) и «не проверялся/не проверялись»; обязательные первыми;
- **Риск** — не подтверждено тестом обязательных N из M; ниже порога теста; грейд не подтверждён / предварительный /
  на ступень выше или ниже запрошенного; нет результата теста; достоверность теста не высокая; формат или город не
  совпали; «вероятно, откажет» (взаимный подбор); особые условия оффера для 14–17 лет;
- **Зарплата** — взаимный фактор вилки и рынок категории на руки;
- место под строку «Основной язык роли: …» (поток Я1): показывается, если в строке подборки есть `core`;
- действия сразу под строками: **Пригласить** (окно оффера с вилкой), **Сравнить** (галочка, до трёх), «Открыть»,
  «Подробнее: тест, ФСП, все причины».

Подробности: на широком блоке (≥ 1000 px — 1440 без проводника) — панель справа (липкая, «Пригласить X» в шапке
панели), иначе — раскрытием под карточкой. «Подробно у всех» раскрывает подробности во всех показанных карточках
(на широком блоке панель справа при этом скрывается).

## Потребность вне каталога (DevOps, mobile, 1С, QA, аналитик данных и т. п.)

У заголовка подборки (`components/NeedScope.tsx`, данные — `selection.scope`, бэкенд `matching/coverage.py:scope`):

- «**Ближайшая категория: Backend** — отдельной категории «DevOps / SRE» нет; частичное соответствие, а не подтверждение
  грейда»;
- «**Проверено тестом:** Linux, Docker» — навыки потребности, по которым в банке направления есть задания (семейства
  банка направления и общий блок, без канареек);
- «**НЕ проверено:** Kubernetes, CI/CD — нет заданий в тесте направления; Terraform, Prometheus — вне справочника; для
  роли — эксплуатация Kubernetes, IaC, облака…». Каждый навык — кнопка «задать вопрос зондом по навыку»;
- «**Задать вопрос зондом (N)**» — окно зонда с выбором вопроса (типовая задача роли или навык) и заготовкой текста
  (`coverage.PROBES`, `probe_for_skill`); получатели — отмеченные «Сравнить», иначе первые три. Оценённый ответ
  становится фактом T1 в карточке (как у любого зонда);
- если по потребности уже есть зонды — ссылка «зонды по этой потребности: N, с ответом K, оценено M» на
  `/employer/probes?need=<id>` (страница зондов показывает только их, «Все зонды» — снять фильтр).

На телефоне (< 640 px) причины («нет заданий…», «вне справочника») и задача роли скрыты — остаются навыки и кнопка.
Для обычной потребности, где тест проверяет все навыки, блока нет; если часть навыков не проверяется — тот же блок с
заголовком «Часть требований тест платформы не проверяет».
