# Устойчивая загрузка интерфейса: никаких белых экранов

Ветка `fix/boot`. Только фронтенд (`frontend/`) и раздача файлов (`frontend/nginx.conf`); backend не меняется.
Что применить на сервере — [infra/nginx/BOOT_APPLY.md](../infra/nginx/BOOT_APPLY.md).

## Зачем

10 октября 2026 г. (журнал nginx стенда, main `2877ca9`):
- основной файл `assets/index-*.js` — 1 227 047 Б, на проводе 418 295 Б (сжатие «на лету», gzip уровня 1, ответ
  `Transfer-Encoding: chunked` без `Content-Length`);
- облачные браузеры из-за рубежа получали его частично: «200» с телом 163 275 … 261 579 Б (шаг 16 384 Б). Замер того
  же дня: соединения из-за рубежа (VPN, облачные браузеры) с сервером в Москве обрываются на ~16 КБ, повторная
  навигация открывает новые соединения и обычно помогает;
- у 5 модельных проверяющих — белый экран: `#root` пуст, `readyState` «interactive», `DOMContentLoaded` не наступил
  (модуль висит). Прежний `/recover.js` подключался блокирующим скриптом в `<head>` и запускал таймер только по
  `load` — при зависшем модуле `load` не наступает, сторож не срабатывал;
- отдельно: под нагрузочным тестом пул БД исчерпывался (docs/LOAD.md), на ошибках API на старте фронт тоже показывал
  пустоту.

Эксперты с VPN и из-за рубежа — в той же зоне риска. Цель: при любом сбое сети или сервера человек видит понятное
сообщение и кнопку, а одна повторная загрузка происходит сама.

## Как устроено — четыре слоя

### 1. Меньше стартового JS (`frontend/src/App.tsx`, `src/lib/lazyPage.ts`, `vite.config.ts`)
- Экраны ролей (кандидат, работодатель, эксперт, ФСП) и тяжёлые экраны (валидация, критерии, графики) — ленивые
  маршруты (`React.lazy` через `lazyNamed`: один модуль — один файл сборки). На старте — общий код и главная.
- React и маршрутизатор — отдельный файл `vendor` (меняется редко, остаётся в кэше между выкладками).
- Меню кабинетов — в лёгких модулях `sections.ts`: меню грузится без экранов.
- Сжатие на сборке (плагин `precompress`): рядом с каждым файлом — `.gz` (уровень 9) и `.br`.
- Таблица стилей сборки — в `<body>` сразу после `#root` (плагин `cssAfterSplash`): зависший CSS не блокирует первую
  отрисовку экрана «Загружаем…».

### 2. Сторож загрузки в `index.html` (встроенный скрипт, без зависимостей и внешних запросов)
- Экран «Загружаем…» — разметка внутри `#root` со встроенными стилями: виден сразу, до любого файла сборки.
- Приложение не смонтировалось за 9 с, файл сборки не загрузился (`error` на `<script>`/`<link>`,
  `vite:preloadError`, отказ динамического импорта), обрезанный файл дал синтаксическую ошибку → сообщение
  «Страница не загрузилась» с подсказкой «Если включён VPN — отключите его и обновите страницу.» и кнопкой «Обновить».
- Одна автоматическая повторная загрузка с обходом кэша (`?r=<метка>`) через 1,2 с; следующая автоматическая — не
  раньше чем через 2 мин (метка в `sessionStorage`; без него — по наличию `?r=` в адресе). Цикла перезагрузок нет:
  второй сбой подряд — только кнопка.
- Перед повтором под service worker — снятие его регистрации и кэшей (как прежний `recover.js`), не дольше 1,5 с.
- После запуска метка `?r=` убирается из адреса (`history.replaceState`).
- Связь с приложением — `window.__fspBoot`: `started()` (код выполняется), `mounted()` (первый экран отрисован —
  сторож больше не вмешивается), `canAuto()`, `retry()` (одна автоповторная загрузка в пределах лимита), `reload()`.

### 3. Экраны после запуска (`src/components/Boot.tsx`)
| Ситуация | Что видит человек |
|---|---|
| файл раздела грузится | «Загружаем…» (через 0,3 с — без мигания на быстрой сети); в кабинете меню остаётся |
| файл раздела грузится > 10 с | «Раздел загружается дольше обычного», подсказка про VPN, «Обновить»; через 1,5 с — одна авто-повторная загрузка |
| файл раздела не загрузился (обрыв, файл прежней выкладки удалён) | «Раздел не загрузился», подсказка про VPN, «Обновить»; через 1,5 с — одна авто-повторная загрузка |
| экран упал при отрисовке | «Что-то пошло не так», «Попробовать ещё раз», «Обновить страницу», «На главную»; переход по меню снимает ошибку |
| `/api/me` на старте: 5xx, обрыв, тайм-аут | «Загрузка…» → через 8 с «Сервер отвечает дольше обычного»; затем «Сервер временно не отвечает», «Повторить», автоповтор до трёх раз (через `Retry-After` сервера или 10 с); вход сохранён, на `/login` не уводит |
| `503 db_busy` / `429` с `Retry-After` | то же, текст «Сервер сейчас перегружен», автоповтор — через `Retry-After` |
| `/api/meta` не ответил | экраны работают без него, тихий повтор через 5, 15 и 45 с |

- ErrorBoundary: `AppErrorBoundary` — верхний уровень (вне маршрутизатора и провайдеров); `ErrorBoundary` из
  `components/ErrorBoundary.tsx` (сброс по адресу страницы, docs/LOAD.md) и `RouteBoundary` маршрутов — один и тот же
  `KeyedBoundary` и один экран ошибки.
- `src/lib/auth.tsx`: 5xx и обрыв сети на `/api/me` не стирают вход (раньше токен удалялся и кабинет уводил на
  `/login`); `401/403/404` — выход, как раньше.
- `src/lib/api.ts`: GET повторяется до 3 раз с паузой `Retry-After` (секунды или HTTP-дата) либо 1 с, 2 с (не дольше
  5 с); `ApiError.retryAfterS`; `isTransient()` — сбой сети или сервера, который имеет смысл повторить.

### 4. Раздача файлов (`frontend/nginx.conf`)
- `gzip_static on` — файлы сборки уходят заранее сжатыми, с `Content-Length`: оборванную передачу браузер видит как
  ошибку загрузки (сторож сразу повторяет), а не ждёт.
- `/assets/` — один заголовок `Cache-Control: public, max-age=31536000, immutable` (раньше `expires` + `add_header`
  давали два); нет файла — 404, а не index.html.
- `/`, `/index.html`, `/sw.js` — `no-cache`: после выкладки браузер сразу получает новые имена файлов.
- Service worker (`public/sw.js`) проверен: навигация — сначала сеть; закэшированный `/` отдаётся только при обрыве
  сети или 5xx и соответствует закэшированным файлам той же версии. Устаревший index при работающей сети не отдаётся.
- HTTP/2 не включается (общий сокет 443 с другими сайтами; при обрыве ~16 КБ одно соединение HTTP/2 хуже нескольких
  HTTP/1.1). Brotli — после сдачи (нет модуля в образе nginx). Подробно — BOOT_APPLY.md, шаги Б и В.

`page.route` так же, как у зарубежных соединений 10.10.

```bash
cd frontend && npm run build
cd ../e2e && AXE_JS=/путь/к/axe.min.js npx playwright test -c playwright.boot.config.ts --project=desktop-1440
npx playwright test -c playwright.boot.config.ts --project=phone-390
```

### Раздача на стенде (после выкладки)
`infra/nginx/check-boot.sh <адрес>` — только чтение: сторож в index.html, нет блокирующего `recover.js`, `no-cache`
у index.html и sw.js, один `Cache-Control immutable` у `/assets/`, `Content-Encoding: gzip` с `Content-Length`,
стартовый JS ≤ 250 КБ на проводе, 404 на несуществующий файл сборки. До выкладки на стенде — 5 провалов; локальный
nginx 1.28 с `frontend/nginx.conf` — 0.

## Чего это не решает
- Обрыв ~16 КБ на соединение — свойство сети между зарубежными узлами и сервером; фронт делает загрузку короче и
  понятнее при сбое, но не чинит сеть. Если повтор не помогает — подсказка «отключите VPN».
- Сторож не перезагружает страницу больше одного раза за 2 минуты: при длительном сбое решает человек (кнопка).
