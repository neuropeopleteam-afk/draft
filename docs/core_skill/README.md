# Ядро роли: основной язык, фреймворк, специализация (Я1, 09.10)

Код — `backend/app/modules/matching/core_skill.py`, порядок — `ranking.selection_order` (подборка `build_selection`,
пакет экспертов `pack2.match_order`), замеры — `tools/core_skill/`, `matching_bench.core_skill_section`,
`tools/realdata/ranking_guard.py`, контроль v2 — `experts/rerank_control.py` + `spectrek/bin/v2-control-check`.

## Зачем
Все три разметчика пакета v2 (модель, не люди) независимо отметили один класс ошибок match-v1: сильный кандидат с
ДРУГИМ основным языком или ядром роли (Java/PHP/C# на Senior Go, не-Python на Python/FastAPI, NLP без CV на CV) стоит
высоко, хотя для нанимающего это «смежное направление». Балл match-v1 этого не видит: Go — один из четырёх обязательных
навыков, а у Java-кандидата подтверждены остальные три.

## Как устроено (без LLM)
1. Ядро — из обязательных навыков потребности (`stack_required`) по словарю направлений:
   Backend, QA, ИБ — основной язык (Python, Go, Java, Kotlin, C#, PHP, JavaScript, TypeScript); Frontend — фреймворк
   (React, Vue, Angular; Next.js — семейство React); Data/ML — специализация (CV, NLP), иначе PyTorch. «Java или
   Kotlin» — любой из двух. Нет такого навыка в обязательном — ядра нет, признак не действует. То, чему работодатель
   обещает научить («обучим React»), ядром не считается.
2. Состояние у кандидата: **подтверждён тестом** (T1 ≥ 0,5, сам или через фреймворк языка: FastAPI → Python),
   **заявлен** (T0, тестом не подтверждён), **не заявлен** (смежное направление).
3. «Нет данных» ≠ «не умеет»: если ядро в пуле подборки не заявлено ни у кого, признак не действует.
4. Порядок (политика `group`): кандидаты без ядра — отдельной группой ниже кандидатов с ядром внутри яруса статуса
   грейда (старше яруса обязательного Ф2). Из выдачи никто не выпадает, причина видна.
5. Объяснение: в шапке карточки подборки и карточки кандидата — «Основной язык роли — Go: не заявлен — ниже в
   подборке» / «…: подтверждён тестом» / «…: заявлен, тестом не подтверждён»; строка «Основной язык роли: Go» в
   «почему»; над подборкой — сводка (сколько подтвердили / заявили / нет) и порядок; в сравнении — строка «Ядро роли»
   и фраза в «почему A выше B».
6. Флаг `RANK_CORE_SKILL`: по умолчанию **включён** с 09.10 после замера ниже (алгоритм `match-v1.2` = match-v1.1 +
   ядро роли); `RANK_CORE_SKILL=0` — прежний порядок match-v1.1, объяснение остаётся без «ниже в подборке».

## Контроль на v2 — только на сервере, один раз
`spectrek/bin/v2-control-check <backend>`: код ветки → временный PostgreSQL 16 из последней копии БД
(`spectrek_fsp_20261009_1648_v2labels`), контейнер образа `spectrek_fsp-api` (`--cpus 1 --memory 1g`, код только для
чтения) → `python -m app.modules.experts.rerank_control`: места подборки пересчитываются кодом ветки при
RANK_CORE_SKILL=0 и =1, P@5 / nDCG@10 — тем же `A.matching_by_pack`, что раздел экспертов `/validation` → печать только
чисел → уборка (trap). Персональные данные сервер не покидают; числа — `v2_control.json`. Смотрели один раз, после
выбора политики; по v2 ничего не менялось. Проверка согласованности: пересчёт без признака воспроизводит замороженные
места v2 (P@5 0,676 и nDCG@10 0,856 — как на `/validation`).

## Решение (п. 7)
bench не хуже (+0,012 nDCG@10), v1 не хуже (+0,004), v2 не хуже (+0,031) → `RANK_CORE_SKILL` включён по умолчанию.

## Ограничения
- Ядро — по словарю: язык вне словаря (Rust, Scala, Swift…) ядром не считается — признак не действует.
- «Заявлен» засчитывается как ядро: кандидат с заявленным, но не подтверждённым Go идёт в группе с ядром (внутри —
  по баллу, где Go без теста уже даёт меньше).
- Все разметки — модель, не люди; бенчмарк — синтетический мир.
