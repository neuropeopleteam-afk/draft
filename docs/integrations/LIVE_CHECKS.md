# Живые проверки интеграций: hh.ru и ATS «Поток»

Что здесь: доказательства, что интеграции работают с настоящими системами, а не только с демо-заглушками.
Ключи и токены в репозиторий не попадают — они хранятся только на сервере (`secrets/*.env`, права 600).

## hh.ru — одобренное приложение работодателя

| Что | Значение | Как проверить |
|---|---|---|
| Заявка на регистрацию приложения | **№30397, одобрена** hh.ru (письмо «Заявка одобрена», получено 10.10.2026) | снимок письма — [`hh_app_30397_approved.png`](hh_app_30397_approved.png); в кабинете разработчика dev.hh.ru (аккаунт работодателя команды) — «Заявка #30397, одобрена» |
| Тип доступа | токен приложения (без входа пользователей hh.ru) | `GET https://api.hh.ru/me` с токеном → `auth_type: application`, `is_application: true` (проверено 11.10.2026 17:45 МСК) |
| Данные | `GET /vacancies`, `GET /vacancies/{id}` → 200 | проверено 10.10.2026 и 11.10.2026 |
| Корпус для проверки подбора | 414 реальных вакансий девяти направлений, собраны 10.10.2026 через API | номера и ссылки — `docs/realdata/hh_match_corpus.json`; методика и итог — `docs/validation/HH_MATCH.md`; тексты вакансий не хранятся (требование ТЗ FTT.6) |
| В продукте | импорт своей вакансии работодателя по ссылке, рынок зарплат по роли и региону (медиана, квартили, n, дата), «что просит рынок» для кандидата | код — `backend/app/modules/hh/`; флаг `HH_ENABLED`; без токена функции скрыты; `HH_STUB=1` — заглушка без сети |

Правила работы с API hh.ru в коде: не чаще 1 запроса в секунду на все процессы, кэш ответов, токен в логи не
попадает, повторный запрос токена не выполняется (он отозвал бы действующий) — `backend/app/modules/hh/client.py`.
