## Объяснения (`matching/ranking.py`, только тексты)

- Навык проверялся тестом, порог не набран: «Проверено заданиями: 1 из 3 — ниже порога подтверждения» (T1, как в сравнении), а не «Нет данных».
- Навык не проверялся: «Не подтверждено: тест кандидата этот навык не проверял, в профиле он не заявлен — можно проверить зондом».
- ФСП: без длинной формулы политики в каждой строке (формула — в паспорте ФСП и карточке).
- Достоверность теста «средняя»/«низкая»: «Не блокирует: на место в подборке не влияет, решение за вами — можно пригласить или
  проверить зондом» (и в карточке кандидата). Это правда: достоверность не входит в скор и не ограничивает приглашения.

## «Что если» (Н1, `matching/whatif.py`)

`GET /api/employer/needs/{id}/selections/{v}/what-if`

- **Полностью подходят** — грейд подтверждён (не «предварительно» и не «не подтверждён») в выбранных категориях версии, каждый
  обязательный навык подтверждён тестом (T1), заявленные формат и город подходят; учитываются и фильтры версии (ФСП, стаж, навыки).
  Это те же правила, что у фильтров подборки (`ranking.apply_filters`), поэтому прогноз «ещё N» совпадает с новой версией (тест).
- Если полностью подходящих меньше 5 — по каждому требованию: сколько подтверждённых оно отсекает само по себе (`cuts`) и сколько
  полностью подходящих появится без него (`options`, только подтверждённые): навык → в желательные, формат, город, соседний грейд
  (категория ниже/выше), фильтры версии. Если по одному ничего не даёт — жадно до трёх вместе («Без Kubernetes и без Go — ещё 5»).
- `apply` — тело для `POST …/selections` (`parent_version`, требования версии, фильтры, подпись `relaxation`): новая версия,
  прежние сохраняются; подпись видна в шапке версии («v2 (из v1: без Linux)»).
- Кандидаты «предварительно», проходящие все требования, — справочной строкой (`provisional_full`), в приросты не входят.
- **Зарплата не отсекает**: минимальные ожидания кандидатов скрыты от работодателя и в подбор не входят, поэтому «без вилки ещё N»
  не считается (это раскрывало бы скрытые ожидания). Если верх вилки ниже рыночного диапазона категории — честная подсказка.
- Скорость: один пул (категории версии + соседние грейды), все варианты — в памяти. На демо-базе 500 кандидатов (SQLite):
  20–170 мс для потребности с направлением, ≈ 0,46 с для всей базы (без направления); повтор — из кэша (2 мин, отметка
  свежести: число и время последних фактов и профилей; ключ — песочница жюри + требования + фильтры).
- Интерфейс: блок над выдачей (`components/WhatIf.tsx`): строка «Полностью подходят: N из M» всегда; при N < 5 — что отсекает
  больше всего и кнопки «Применить как vN»; при N ≥ 5 — «Оставить только полностью подходящих».
- Демо: в песочнице жюри потребность «Backend-разработчик senior для платёжного шлюза» (PostgreSQL, Kafka, Linux, удалённо) и шаг
  проводника «Подборка мала: «Что если»».
