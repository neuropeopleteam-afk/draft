# Банк заданий «Драфт»: как устроен и как проверен

Для жюри и экспертов. Банк — дерево `backend/assessment_bank`, хэш содержимого `913ad19f6a259aff` (на этом же банке посчитан итоговый прогон точности вердикта по грейду). Документ собран командой `python3 tools/bank_jury_doc.py` из отчётов прогонов — чисел, вписанных руками, здесь нет; у каждого раздела указан файл-источник.

## Главное за минуту

- **1 646 семейств заданий по 10 ИТ-направлениям.** Семейство — не один вопрос, а генератор: секретное серверное зерно выбирает числа, имена, фрагменты кода и порядок вариантов, ключ вычисляется кодом для каждого варианта. У расчётных и кодовых заданий выученный ответ одного варианта не подходит к другому; у концептуальных меняются формулировки, данные и порядок вариантов.
- **Ключи проверены исполнением:** на 20 зёрнах — 32 920 вариантов, 38 131 проверок ключа запуском кода, не прошло 0, семейств с ошибкой — 0.
- **Знание кода почти не помогает:** «изучивший открытый код» генераторов угадывает букву ответа в 20,7 % при случайном выборе 20,8 %; «решатель без знаний» (эвристики по числам вариантов, задания с числовым выбором) — 21,9 % при 20,4 %.
- **Независимая сверка:** модель другой компании решала задания вслепую — совпала с ключом в 93,5 % (144 из 154); каждое расхождение разобрано: часть — неточность формулировки (условие уточнено), часть — разброс самой модели; ключи не менялись.
- **Честно:** трудность заданий — априорная (до калибровки на людях); слабые места перечислены в конце.

## Как задание доходит до кандидата

- Сервер выбирает следующее семейство адаптивно (по информативности у ближайшего порога грейда) и берёт для него зерно из криптостойкого генератора случайных чисел (диапазон ≈ 2·10⁹): заранее перебрать варианты нельзя, у каждого кандидата — свой вариант.
- Кандидату уходит только условие, код и варианты ответа текущего шага. Ключ, рубрика, номер семейства и зерно остаются на сервере; задание адресуется случайным токеном (по «семейство:зерно» открытый генератор восстановил бы ключ). Это закреплено автотестом публичного вида (`tests/test_bank_public_view.py`).
- Семейства прошлых попыток кандидата по направлению повторно не выдаются; повторная попытка — другой субпул (параллельная форма).
- 12 семейств — «канарейки»: часть их вариантов намеренно опубликована, в грейд они не входят. Кто читал утечку, отвечает на них заметно быстрее и чаще верно, чем предсказывают его ответы на чистых заданиях; тогда θ пересчитывается без подозрительных ответов (`backend/assessment_bank/psychometrics/preknowledge.py`).
- Код кандидата на сервере не исполняется: ответы сверяются с ключом, вывод программ — после нормализации; открытые ответы оцениваются по рубрике.

Источник — `backend/app/modules/assessment/bank_engine.py` (описание модуля), `backend/assessment_bank/schema.py` (`public_view`).

## Что выведено из выдачи и почему

- 320 семейств старших грейдов первой версии: при проверке оказалось мало разных шаблонов — выведены до переработки (`backend/assessment_bank/families_retired/lp_v2_2010/README.md`).
- 55 семейств, где ключ узнаётся по форме варианта (длина, текст) у того, кто уже видел семейство: правило вывода — атака угадывает ≥ 75 % (втрое выше шанса) (`backend/assessment_bank/families_retired/form_leak_2110/README.md`). Генераторы сохранены — переделка после финала.
- 13 семейств, где верный ответ по смыслу повторяется во многих вариантах (один тип дефекта на семейство, меняются код и имена), оставлены с пометкой «утечкоустойчивость ниже» (`leak_resistance: low`).

## Честно о слабых местах

- Параметры трудности (a, b) — априорные: a = 1,0 у выбора ответа и 1,3 у практических, b — у порога грейда по содержательной оценке. Калибровки на людях нет; в каждом YAML это написано в поле `basis`.
- У Principal доля выбора ответа 79 % (у Lead — 40 %): практические задания старших грейдов — первая задача после финала.
- Мутации решения для go/java/bash/sqlite/git не реализованы (56 семейств вне знаменателя); выжившие мутанты не «добиваются» — оценка консервативная.
- Атака «по форме» на концептуальных заданиях даёт 24,3 % при 20,8 %: тот, кто видел семейство, угадывает немного чаще случайного. Для расчётных и кодовых заданий это не работает — ключ вычисляется заново.

## Вопросы экспертов — короткие ответы

**Что если задания утекут в сеть?** Утекают варианты, а не ключи: каждый показ — новое зерно сервера. Даже зная код генераторов, букву ответа угадывают не чаще случайного (20,7 % при 20,8 %).

**Кто гарантирует, что ключ верный?** Код: для расчётных и кодовых заданий ключ получается запуском эталона и тестов (38 131 проверок, 0 не прошло). Плюс сверка вслепую моделью другой компании — 93,5 %, расхождения разобраны (уточнены условия, ключи не менялись) — `docs/bank/blind_solve_review.md`.

**Почему трудность не откалибрована?** Нет людей с подтверждённым грейдом в нужном числе. Поэтому параметры честно помечены «априорные», а точность вердикта считается на симуляции с указанием условий.

**Не подсказывает ли текст задания грейд?** Нет: проверка «грейд в условии» — 0 совпадений на 1 646 семействах × 20 зёрнах.

**Можно ли проверить самим?** Да, команды ниже; любой вариант можно получить командой `python -m assessment_bank generate <семейство> <зерно> --public` (ровно то, что видит кандидат).
