# Устная защита ответа и ИИ-интервью

Модуль `backend/app/modules/interview` (продуктовая часть: модели, API, лимиты, согласие, экраны) и движок
`backend/app/modules/interview/engine` (разговор и оценка, интерфейс — `engine/CONTRACT.md`, ветка движка). Всё —
за флагом `INTERVIEW_ENABLED` (по умолчанию выключен): без флага нет ни панелей, ни значков, ни строк в сравнении, а API
отвечает `409 interview_disabled`.

**Главное правило (FTT.4): грейд официально ставит только тест.** Устная защита и ИИ-интервью грейд не меняют, в
ранжирование подборки не входят — это отдельный сигнал доверия рядом с результатом теста. Оценку делает модель, не люди;
решение остаётся за работодателем.

## 1. Два режима

| | Устная защита ответа | ИИ-интервью — этап найма |
|---|---|---|
| Кто начинает | кандидат, по желанию | работодатель в принятом приглашении |
| О чём вопросы | собственные развёрнутые ответы кандидата в тесте (от 120 знаков) и темы заданий | навыки потребности, которые тест не подтвердил (или навыки, указанные работодателем) |
| Длительность | 3 минуты, до 3 вопросов (`INTERVIEW_DEFENSE_MINUTES`, `…_MAX_QUESTIONS`) | 10 минут, до 6 вопросов (`INTERVIEW_HIRING_MINUTES`, `…_MAX_QUESTIONS`) |
| Итог | «ответ подтверждён устно» / «есть расхождения» / «мало данных» | «сильный / средний / слабый результат» / «мало данных» |
| Кто видит итог | кандидат и работодатели, открывшие его карточку | только пригласившая компания; кандидату — статус |

### Где в интерфейсе

* Кандидат: панель «Подтвердите авторство ответа: устная защита 3 минуты, по желанию» — на итоге попытки
  (`/candidate/assessment`), в «Категории и грейде» (`/candidate/category#defense`) и над «Двумя попытками»
  (`/candidate/attempts`). Разговор — `/candidate/interview/<id>`. Приглашение на ИИ-интервью — в окне принятого
  приглашения (`/candidate/invitations`).
* Работодатель: значок в подборке и на карточке («ответ подтверждён устно / расхождения / мало данных / не проходил»),
  строка «Устная защита ответов» в сравнении, подробности на карточке кандидата (`/employer/candidates/<ref>`): вопросы,
  подтверждённые цитаты, замечания, текст разговора под раскрытием. Этап «ИИ-интервью» — в карточке приглашения
  (`/employer/invitations`).
* Жюри: в песочнице есть готовый пример с подписью «пример, модельный кандидат» (Мария — «подтверждено устно», Илья — «есть
  расхождения»); живой запуск — с лимитами (раздел 4). Шаг «Устная защита ответа · по желанию» в проводнике «12 минут»
  появляется при включённом флаге (поле `interview_enabled` в `/api/meta`).

## 2. Механика разговора

1. Согласие (версия `2026-10-10.2`) и имя для обращения (без фамилии). Без согласия сессия не создаётся (`422`).
2. Канал: **голос → текст**. Аватара поставщика и изображений людей в продукте нет (регламент ЛЦТ, п. 5.11 — без
   изображений третьих лиц): собеседник на экране — собственная анимация «Интервьюера» (круг с волной голоса на
   `<canvas>`, раздел 2.1), подпись «модель, не люди»; при `INTERVIEW_AVATAR_ENABLED` — свой образ
   «ИИ-интервьюер, не человек» (сгенерированный портрет несуществующего человека и беззвучные клипы, раздел 2.2). Голос ведущего — синтез речи
   движка (`…/speech`, mp3, стоковый голос поставщика); нет голоса — вопросы показываются текстом. Переход записывается
   в сессию (`channels_log`), кандидат видит короткое пояснение, а не ошибку. Канал «аватар» поставщика (Anam) остаётся
   только внутри движка за `INTERVIEW_ANAM_ENABLED` (по умолчанию выключен) и экраном не используется.
3. Ответ — «нажми и говори» (запись одного ответа целиком, распознаётся на сервере, кандидат видит и может поправить
   текст перед отправкой) или текстом. Аудио не хранится: после распознавания остаётся только текст.
4. Ведущий задаёт вопросы по плану движка, разговор заканчивается по числу вопросов или по времени; кандидат может
   закончить сам — оценивается то, что есть.
5. Оценка идёт в фоне (статус «Оценивается моделью»), затем итог записывается в сессию и в факт результата теста
   (`value.defense`) — оттуда его берут карточка, подборка и сравнение.

### 2.1. Визуал собеседника и общие голосовые компоненты

`frontend/src/components/voice/` — без внешних зависимостей (getUserMedia, MediaRecorder, Web Audio); ими же
пользуется голосовой ввод потребности.

| Что | API | Поведение |
|---|---|---|
| `VoiceWave` | `<VoiceWave state level? name? caption? size? />`, `state`: `idle` \| `listening` \| `speaking` \| `thinking` | круг с кольцом-волной: «говорю» — волна от уровня звука ведущего, «слушаю» — от уровня микрофона (или спокойное «дыхание»), «думаю» — бегущие точки, «ожидаю начала» — неподвижно; подпись состояния текстом (`aria-live`), `prefers-reduced-motion` — статичный кадр; `data-state` для e2e |
| `useVoiceRecorder` | `useVoiceRecorder({ maxSeconds=90, maxBytes=3 МБ, onBlob(blob, seconds), onError(message, code) })` → `{ state, seconds, level(), supported, start(), stop(), cancel() }` | явное разрешение микрофона, запись `audio/webm` (или что умеет браузер), остановка по пределу длительности, поток микрофона закрывается сразу; коды отказа `unsupported \| denied \| no_device \| too_large \| empty \| failed` с текстами по-русски (`REC_MESSAGES`) |
| `VoiceRecordButton` | `<VoiceRecordButton transcribe={(b) => postAudio(path, b)} onText(text, {stub, seconds}) onNote? onState? onLevel? maxSeconds? />` | кнопка «Нажми и говори» / «Остановить запись · 0:12 из 1:30» / «Распознаём…»; распознанный текст отдаётся экрану в поле на проверку — ничего не отправляется само |
| `postAudio(path, blob)` | → `{ text, stub }` | POST записи телом запроса с токеном; ошибка — `ApiError` с текстом сервера |
| `useSpeechPlayer()` | → `{ audioRef, unlock(), play(blob), stop(), playing, level() }` | проигрывание mp3 через `<audio>` с анализатором уровня для `VoiceWave`; `unlock()` — из нажатия кнопки (правило автозапуска) |

Состояния экрана разговора: «думаю» — пока сервер готовит вопрос, распознаёт запись или модель оценивает; «говорю» —
пока звучит голос ведущего (в чате — пока человек читает вопрос, по длине текста 1,2–4 с); «слушаю» — ждёт ответа или
идёт запись.

### 2.2. Свой образ интервьюера (`INTERVIEW_AVATAR_ENABLED`, по умолчанию выключен)

Решение владельца 11.10: вместо круга с волной — собственный образ интервьюера, **сгенерированный моделью**: реалистичный
портрет несуществующего человека (не фото и не образ реального человека, изображений третьих лиц нет — п. 5.11;
выбор владельца — вариант 1 из 4; первый вариант, плоская иллюстрация, заменён), «оживлённый» короткими беззвучными
клипами; на экране — «ИИ-интервьюер, не человек».
Включается флагом api `INTERVIEW_AVATAR_ENABLED=true` (только вместе с `INTERVIEW_ENABLED`); фронт читает
`/api/meta` → `interview.avatar`. Выключен — экран как в разделе 2.1 (`VoiceWave`, без `<video>`).

| Что | Где | Поведение |
|---|---|---|
| Файлы | `frontend/public/avatar/`: `interviewer.webp` (480×480, 15 КБ), `{idle,speaking,listening,thinking}.{webm,mp4}` (384×384, 8 с «вперёд-назад», 84–171 КБ каждый, без звуковой дорожки), `silent.vtt`, `PROVENANCE.md` (модель, дата, запросы, обработка) | клипы — `veo_3_1_fast` image-to-video по портрету `gpt_image_2_5_flare`; webm (VP9) — где браузер умеет, иначе mp4 (H.264) |
| `InterviewerAvatar` | `frontend/src/components/voice/InterviewerAvatar.tsx`, `<InterviewerAvatar state level? name? caption? size? />`, те же `state`, что у `VoiceWave` | состояние разговора → свой клип («ожидаю начала» / «говорю» / «слушаю» / «думаю»), смена — плавным переходом 0,3 с; рамка светится по уровню звука (голос ведущего или микрофон) |
| Ленивая загрузка | — | клипы грузятся, только когда образ на экране (`IntersectionObserver`), сначала текущий, остальные — после его готовности; картинка — `loading="lazy"` |
| Запасной вариант | — | нет клипа / ошибка загрузки / «экономия трафика» → неподвижный кадр, рамка светится по громкости голоса ведущего, «думаю» — бегущие точки в углу (рисованный рот поверх фотореалистичного портрета выглядит неестественно — проверено, его нет); нет и кадра — градиент ФСП |
| `prefers-reduced-motion` | — | без клипов и без движения: неподвижный кадр, цвет рамки по состоянию, состояние — текстом |
| Доступность | — | `<figure>` с подписью «Интервьюер: говорю/слушаю/думаю» (`aria-live`) и «ИИ-интервьюер, не человек · модель, не люди · …»; на кадре — плашка «ИИ · не человек»; у кадра — описание (`alt`: «сгенерирован моделью, несуществующий человек»), клипы `aria-hidden`, без звука, с пустой дорожкой субтитров; `data-state` / `data-mode` (`video` \| `still`) для e2e |

Голос и распознавание — без изменений (раздел 2.1). Живой аватар (Anam) этим флагом **не** включается — у движка
для него отдельный `INTERVIEW_ANAM_ENABLED` (выкл.), см. 2.4.

### 2.4. Живой аватар с нашим лицом (Anam, флаг `INTERVIEW_ANAM_ENABLED`, по умолчанию выключен)

Тот же образ, что в 2.2, но живой: наш сгенерированный портрет (несуществующий человек, `frontend/public/avatar/PROVENANCE.md`)
загружен в Anam как **собственный аватар** (`ANAM_AVATAR_ID`, `engine/DEPLOY.md`), стоковые лица поставщика не используются.

| Что | Как |
|---|---|
| Включение | `INTERVIEW_ANAM_ENABLED=true` + `ANAM_API_KEY` + `ANAM_AVATAR_ID` (файл `secrets/anam.env`, `env_file` у `api`); в ответе сессии `conversation.channels.avatar=true`. Без флага маршрут токена — 503 `avatar_unavailable`, экран — как в 2.2 |
| Поток | экран (канал «голос», идёт разговор) берёт одноразовый токен `POST /api/interview/sessions/{id}/avatar-token` (ключ не покидает сервер), поднимает WebRTC официальным `@anam-ai/js-sdk` (ленивый импорт — без флага код поставщика в браузер не грузится), `disableInputAudio` — микрофон кандидата в поток не идёт |
| Голос | **наш** женский голос ElevenLabs: `GET /speech?format=pcm` (pcm_s16le 16 кГц моно) → `createAgentAudioInputStream().sendAudioChunk` → Anam рисует губы и отдаёт звук в потоке (режим передачи звука); LLM и голос Anam не задействованы, вопросы — наш движок |
| Откат | любой сбой (503 токена, нет WebRTC, таймаут 12 с, разрыв, предел сессии `ANAM_MAX_SESSION_S`) — тихо: портрет и клипы 2.2, голос mp3; пока поток поднимается — портрет под видео, первый вопрос ждёт поток не дольше 4 с |
| Экран | под образом только «Интервьюер: говорит / слушает» (решение владельца 11.10), `data-mode="anam"` для e2e |
| Учёт | `avatar_usd` — оценка по минутам разговора × `INTERVIEW_PRICE_AVATAR_MIN` при выдаче токена |

## 3. Как оценивается

Движок (раздел 3 `engine/CONTRACT.md`): аналитик → скептик → **сборка кодом** (замечания скептика применяются
детерминированно) → **сверка цитат кодом** с расшифровкой → уровни вопросов → балл → вердикт по таблице:

| Вердикт | Когда |
|---|---|
| подтверждено устно | нет «расхождения», балл ≥ 70 |
| есть расхождения | есть «расхождение» или балл < 50 |
| мало данных | ответов < 2, или суммарно < 150 знаков, или 50 ≤ балл < 70 без «расхождения» |

Уровень «подтверждено / частично» без сверенной цитаты понижается до «нет данных», «расхождение» без цитаты — до
«частично»: обвинять без доказательства нельзя. Продукт **ещё раз** сверяет каждую цитату с репликами кандидата и
отбрасывает несовпавшие (`quotes_dropped`); работодатель видит только цитаты, найденные в расшифровке.

Без ключа модели (или `INTERVIEW_STUB=1`) движок работает заглушкой; `INTERVIEW_ENGINE=stub` — заглушка продукта без
движка. Вопросы — по шаблону, оценка — правилом по пересечению значимых слов с письменным ответом, итог помечен
«заглушка». На заглушке идут тесты, CI и e2e; `INTERVIEW_STT_STUB=true` (только e2e/демо) — «нажми и говори» в заглушке
возвращает начало письменного ответа текущего вопроса с пометкой «распознавание — заглушка».

### Автопроверка на модельных кандидатах (модель, не люди)

`tools/interview_autocheck/` (ветка движка): три роли — честный, списавший, «плавающий» — защищают одни и те же
письменные ответы; итог — строка «честных подтверждено X из Y, списавших поймано Z из W» с датой, коммитом и моделями,
файлы `tools/interview_autocheck/results/<дата>_<sha>.md|json`.

| Прогон (ветка движка) | Роли | Итог (модель, не люди) |
|---|---|---|
| 10.10 13:53 МСК, `a386273`, файл `20261010_1053_a386273.md` | честный × 2, списавший × 2 | честных подтверждено **2 из 2**, списавших поймано **2 из 2**, «мало данных» — 0; 1,38 USD |
| 10.10 14:04 МСК, `0f2f97a`, файл `20261010_1104_0f2f97a.md` | «плавающий» × 2 | «плавающих» не подтверждено **2 из 2** («есть расхождения», баллы 10 и 43) |

Модели: реплики — anthropic/claude-sonnet-4.6, оценка — anthropic/claude-fable-5.1, модельный кандидат —
anthropic/claude-sonnet-4.6. Это 6 модельных сессий, по 2 на роль, — мало для точности: числа показывают, что механика
различает честный и чужой ответ на сценариях, а не точность на реальных кандидатах. Новые прогоны — в том же каталоге;
без файла результата чисел здесь нет.

## 4. Лимиты и стоимость

* Кандидат: до 4 новых сессий в сутки, до 2 сессий на одну попытку теста (сбой связи — можно ещё раз).
* Всего по стенду: до 300 новых сессий в сутки (`INTERVIEW_TOTAL_DAY`) и дневной потолок расходов движка
  `INTERVIEW_DAILY_CAP_USD` (по умолчанию 15) — превышение → `429 daily_cap`, идущие сессии доводятся.
* Песочница жюри: живой запуск не чаще 1 раза в час на песочницу и не длиннее 5 минут (`429 jury_limit`, рядом — готовый
  пример).
* Стоимость сессии (`cost`): доля модели — от движка, распознавание и голос — считает продукт по ставкам движка;
  `estimated: true`, если цена оценочная.

## 5. Персональные данные

* Согласие обязательно и версионируется; оператор — из `app/core/legal.py`.
* В модель уходят только письменные ответы и реплики: имя из профиля заменяется на «[имя]», фамилии, контакты и
  резюме не передаются (`context.py`, NER из модуля резюме). Обращения к зарубежным API — через ретранслятор движка.
* Хранится текст разговора и результат, без видео и звука. Кандидат удаляет запись и результат кнопкой
  (`DELETE /api/interview/sessions/<id>`), значок у работодателя пропадает. Остаётся только отметка о факте сессии
  (статус «удалено», без текста и результата): удаление не даёт пройти защиту той же попытки заново — следующая
  возможность будет у следующей попытки теста.
* Текст разговора видит работодатель (защита — любой, открывший карточку; ИИ-интервью — только пригласившая компания);
  кандидату итог ИИ-интервью компании не показывается.

## 6. Настройки

Продукт (`app/core/config.py`): `INTERVIEW_ENABLED` (выкл.), `INTERVIEW_ENGINE` (`auto` — движок, если пакет
`engine/` есть; `stub` — заглушка), `INTERVIEW_AVATAR_ENABLED` (выкл.; свой образ интервьюера, раздел 2.2),
`INTERVIEW_STT_STUB` (выкл.; только e2e/демо), `INTERVIEW_AUDIO_MAX_KB`, `INTERVIEW_DEFENSE_*`,
`INTERVIEW_HIRING_*`, `INTERVIEW_PER_USER_DAY`, `INTERVIEW_TOTAL_DAY`, `INTERVIEW_JURY_MINUTES`,
`INTERVIEW_JURY_PER_HOUR`. Движок (ключи, модели, ретранслятор, TURN, потолок расходов) — раздел 5
`engine/CONTRACT.md` и `engine/DEPLOY.md`. Миграция — `iv01_interview_sessions` (таблица `interview_sessions`).

## 7. API

`/api/interview/defense/{test_session_id}` (GET состояние, POST создать), `/api/interview/sessions/{id}` (GET, DELETE),
`…/begin`, `…/answer`, `…/finish`, `…/transcribe` (тело — запись, ответ `{text, stub}`), `…/speech` (mp3), `…/channel`
(`voice` \| `text`),
`/api/interview/candidates/{ref}` (работодатель), `/api/employer/invitations/{id}/ai-interview` и
`/api/candidate/invitations/{id}/ai-interview`. Модели ответов — в OpenAPI (`/api/docs`, тег `interview`).

  звука; при `prefers-reduced-motion` — неподвижный кадр без `<video>`), первый ответ — «нажми и
  говори» с фальшивого микрофона Chromium (при `INTERVIEW_STT_STUB=true`), итог, значок и подробности у работодателя;
  этап найма: приглашение → кандидат проходит ИИ-интервью на 390 px → итог у работодателя; 390 px без горизонтальной
  прокрутки, снимки; axe (`E2E_AXE=<путь к axe.min.js>`) без нарушений serious/critical. При выключенном флаге тесты
  пропускаются. Окружение api для этих тестов: `INTERVIEW_ENABLED=true INTERVIEW_ENGINE=auto INTERVIEW_STUB=1
  INTERVIEW_STT_STUB=true INTERVIEW_JURY_PER_HOUR=3` (защита и ИИ-интервью в одной песочнице), ключи поставщиков
  пустые; на локальной SQLite — ещё `JURY_SPARE_SANDBOXES=0` (фоновая запасная песочница жюри пишет в базу
  одновременно со входом, SQLite отвечает «database is locked», и пример защиты в песочнице не создаётся).

## 9. Ограничения

* Пока движок не выложен или нет ключей, на стенде работает заглушка — она честно помечена в интерфейсе.
* Распознавание и синтез речи зависят от внешних поставщиков; сбой переводит разговор на текст.
* Устная защита не доказывает и не опровергает списывание: она показывает, может ли кандидат объяснить свой ответ
  своими словами. Читать её стоит вместе с признаками целостности теста.
