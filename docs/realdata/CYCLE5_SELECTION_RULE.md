# Цикл №5 — правило выбора варианта (записано ДО перебора)

Гипотеза (Победа, 21.10): когда работодатель указал грейд, по умолчанию сначала точное совпадение уровня, затем
«верхний край» и добор — порядок, не фильтр (никто не скрыт); опция «строго запрошенный грейд» остаётся.

Варианты порядка по умолчанию внутри яруса статуса грейда и ступени стека (match-v2, веса не переобучаются):
- V0 — как №4 (балл match-v2);
- V1 — по вероятности «уровень именно запрошенный» (как опция grade_exact), затем балл;
- V2 — то же, вероятность с шагом 10 % (корзины), внутри корзины — балл;
- V3 — только «сильнее запроса» (in_band < 0,5) ниже, остальное — балл.

Данные выбора — только разработка: наши миры `bench_holdout2.py run --dev` (зёрна 31000001/2, S-M, «идеальный», S-M 55 %,
жёсткие) и Dev_dev зёрна 1–3 (строка main). Отложенные миры №3/№4 и зёрна Dev_dev 2026, 77021161–65, 77021191–96 не
используются.

Правило: допустимы варианты, у которых S-M rel nDCG@10 на разработке упал не больше полуширины 95 % ДИ V0 на S-M
разработки, и жёсткие rel nDCG@10 — тоже не больше полуширины своего ДИ. Из допустимых выбирается вариант с наибольшим
nDCG@10 Dev_dev main (зёрна 1–3); при равенстве до 0,001 — меньший номер. Если ни один не выше V0 на Dev_dev более чем
на 0,005 — остаётся V0 (№4), FREEZE №5 не делается.
