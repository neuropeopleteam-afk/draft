# Индекс официальных протоколов соревнований ФСП России (`fsp_protocols`)

Модуль `tools/fsp_protocols` обеспечивает автоматическое подтверждение спортивных достижений, разрядов (`МС`, `КМС`, `I`–`III`) и призовых мест кандидатов на основе **19 официальных открытых документов** Общероссийской физкультурно-спортивной общественной организации «Федерация спортивного программирования» (ОФСОО «ФСП») и Министерства спорта Российской Федерации, опубликованных на [`https://fsp-russia.ru/about/documents/`](https://fsp-russia.ru/about/documents/).

---

## 1. Сводная статистика индекса

Числа не пишутся в README руками: актуальные значения — в `index_stats.json` (документы, результаты, спортсмены,
субъекты РФ, нормативы ЕВСК), `aggregates.json` (агрегаты без ПДн), `ocr_audit_v5.json` (независимый аудит итогового индекса; `ocr_audit.json` — аудит v2, история),
`index_v5_report.json` (что удалено и исправлено при сборке; `index_v4_report.json` — история),
`place_recover_summary.json` (восстановление мест, см. ниже), `evsk_examples.json` (5 реальных записей с выводом ЕВСК,
обезличенно), `retable_summary.json` (повторный разбор командных протоколов). Пересчёт — поле `recompute` в каждом файле.

### Места: почему у записи нет числа (index_v5)

У каждой записи — `place_status` (счёт — `index_stats.json → place_status_counts`):

| `place_status` | Что это | Откуда |
|---|---|---|
| `placed` | место — одно число | протокол |
| `shared_range` | место поделено: «14-24», «9-10» — `place_range: [a, b]`, `place = null`; норматив ЕВСК считается по худшему месту `b` | протокол |
| `no_place` | «б/м» — без места (0 баллов) | протокол, по построению |
| `disqualified` | «б/м» в месте и DSQ в баллах | протокол, по построению |
| `not_a_protocol` | список кандидатов в сборную — мест нет | документ, по построению |
| `not_recognized` | таблица не распознана | разбор |

`place_uncertain = true` (в ЕВСК — статус `place_unverified`) — место прочитано, но не подтверждено вторым независимым
чтением. Как восстановлены места, которых не было в index_v4 (`tools/fsp_protocols/place_recover.py`): текст ячейки «Место»
переписывается дословно двумя поставщиками распознавания; место подтверждается их совпадением и (где найдены линии
таблицы — `team_geometry.block_row_counts_v2`) совпадением блоков команд с линиями; продолжение команды на новой странице —
только если место подтверждено на предыдущей; пустая ячейка между подтверждёнными местами k и k+2 → k+1 (`sequence`).
Проверяющая модель независимого аудита (`ocr_audit_v4.py`) в восстановлении не используется.

### Независимый аудит итогового индекса (`ocr_audit_v5.json`)

Протокол зарегистрирован в git до сверки (`ocr_audit_v4_plan.json`: зерно из SHA-256 файла индекса, 155 записей из
14 документов, стратификация по протоколам, SHA-256 выборки). Проверяющая модель — третьего поставщика (не участвовала в
построении индекса), ФИО ей не передаётся: она переписывает все строки страницы, сопоставление — кодом после ответа.
Один прогон, затем каждое расхождение разобрано глазами по изображению страницы; итог — по разбору. Значения, интервалы
и причины расхождений — в самом файле (`errors`, `adjudication_notes`); оговорка про неразобранные совпадения — там же.
Найденные ошибки исправлены в `index_v6.json` (`tools/fsp_protocols/apply_audit_fixes.py`, правила — вне git, в
`data_local/…/work/ocr_audit_v4/fixes.json`, т.к. содержат ФИО); числа индекса после исправлений — `index_stats.json`.

## 2. Соблюдение 152-ФЗ и Положения ФСП об обработке персональных данных

Сверено с «Положением об обработке и защите персональных данных» ОФСОО «ФСП» (утв. приказом ФСП от 29.08.2023 № 27,
https://fsp-russia.ru/about/documents/ , файл `kcf7c5gmd5…pdf`, SHA-256 — в `documents.json`).

| Положение ФСП | Что там сказано | Как у нас |
|---|---|---|
| п. 3.1 — цели | «подготовка и использование официальных протоколов соревнований», «организация системы учёта данных о спортсменах… спортивную квалификацию» | Используем только опубликованные протоколы и только для подтверждения результата самого спортсмена. |
| п. 3.2 — категории | ФИО, дата рождения, сведения о спортивных достижениях (результаты соревнований) | Берём из протокола только ФИО, дату рождения, субъект РФ, команду, место, разряд. Тренеры, судьи, подписи, персонал из индекса исключены. |
| п. 4.3 — несовершеннолетние | до 14 лет — только с согласия законного представителя | В протоколах есть школьники. Сверка на платформе — только по запросу самого совершеннолетнего кандидата; для младше 18 лет — с согласия законного представителя (требование к ЛК кандидата). |
| п. 4.4 — согласие через заявку | подача заявки на соревнование признаётся согласием на обработку для целей соревнования | Это согласие дано ФСП, а не нам, поэтому основание нашей обработки — отдельное согласие кандидата на сверку (ст. 6 152-ФЗ), а не факт публикации протокола. |
| п. 4.7, 7.2 — передача третьим лицам | без письменного согласия субъекта не допускается | Чужие ФИО никому не показываются; работодатель видит только результат сверки кандидата, давшего согласие (дисциплина, место, норматив ЕВСК, ссылка на протокол). |
| приложения № 2, 4 — распространение | согласие на размещение данных на сайте ФСП | Открытого каталога спортсменов на платформе нет; публичные агрегаты (`aggregates.json`, `index_stats.json`) не содержат ФИО и дат рождения — проверяется автотестом. |
| п. 5.1, 6.2–6.6 — сроки, уничтожение | прекращение по отзыву согласия; уничтожение в течение 30 дней после достижения цели | Отзыв согласия кандидатом удаляет результат сверки из его ЛК. Промежуточные данные (изображения страниц, OCR) удаляются после сборки индекса. |
| п. 7.1 — меры защиты | правила доступа, учёт действий | Индекс — вне git в `/opt/spectrek_fsp/data_local/fsp_protocols/` (права 600, владелец — процесс API). Ключи сверки — HMAC-SHA256 с серверным секретом (`FSP_INDEX_HMAC_KEY`), без секрета хэш не перебирается по словарю ФИО. |

Остаётся за пределами кода (честно):
- Правильный путь в бою — сверка через ФСП ID/API федерации, а не повторная обработка PDF. Индекс по протоколам —
  временное решение для пилота.
- В git-истории остались 3 несолёных SHA-256 хэша ФИО в `sample_anonymized.json` (коммиты до HMAC) — передано
  оркестратору для очистки истории.
- В серверном индексе ФИО хранится и в открытом виде (`fio_norm`) — нужно для нечёткого сравнения (ё/е, опечатки OCR);
  доступ только у процесса API.

## 3. Схема записи индекса

Каждая запись в `records` серверного индекса `/opt/spectrek_fsp/data_local/fsp_protocols/index.json` имеет вид:

```json
{
  "key_hash": "<hmac-sha256>",
  "fio_hash": "<hmac-sha256>",
  "fio_norm": "<в серверном индексе вне git; в sample_anonymized.json удалено>",
  "birth_date": "<YYYY-MM-DD или YYYY в серверном индексе; в sample_anonymized.json удалено>",
  "discipline": "программирование алгоритмическое",
  "event_title": "Список кандидатов в спортивные сборные команды РФ по спортивному программированию на 2026 год",
  "ekp_no": "СБОРНАЯ-РФ-2026",
  "date": "2026-05-14",
  "place": 1,
  "rank": "КМС",
  "team": "РФСОО \"Федерация спортивного программирования в г. Москва\"",
  "region": "Москва",
  "pdf_url": "https://fsp-russia.ru/upload/iblock/503/e5miei2aikivxs93d6qz2iqfnfaf0xp1.pdf",
  "page": 4
}
```

- `key_hash` — `SHA-256` от строки `"{fio_norm}:{birth_year}"` (если год рождения известен) или от `"{fio_norm}"` (либо `team:{team_norm}` для командных отборочных протоколов без поимённого списка).
- `fio_hash` — `SHA-256` от канонического `fio_norm` (нижний регистр, `ё -> е`, один пробел), позволяет находить записи даже если кандидат не указал дату рождения или она отсутствует в протоколе соревнования.
- `ekp_no` — официальный 16-значный номер соревнования в Едином календарном плане Минспорта России (например, `2101620020035562`, `2101590019043742`, `2101770020035561`) или код всероссийского реестра.
- `pdf_url` и `page` — прямая ссылка на официальный PDF-протокол на сайте `fsp-russia.ru` и номер страницы, на которой находится строка участника.

## 5. Как пересобрать индекс и как вызывать проверку из бэкенда

### Сборка индекса из первоисточников
```bash
OPENROUTER_API_KEY=... python3 -m tools.fsp_protocols build \
  --pdf-dir /tmp/fsp_pdfs \
  --cache-dir /tmp/fsp_pdfs/cache \
  --out /opt/spectrek_fsp/data_local/fsp_protocols/index.json \
  --sample-out docs/realdata/fsp_protocols/sample_anonymized.json
```

### Проверка кандидата или команды в Python (для модуля `app/modules/fsp/`)
```python
from tools.fsp_protocols.lookup import verify_candidate_fsp

result = verify_candidate_fsp(fio="...", birth_date="2004-06-02")
# result["verified"] -> True
# result["highest_rank"] -> "КМС"
# result["achievements"] -> список словарей с discipline, event_title, ekp_no, place, rank, pdf_url, page
```
