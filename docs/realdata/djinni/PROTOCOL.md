# Протокол внешнего бенчмарка подбора на открытом наборе Djinni (А17, 21.10.2026)

Протокол зафиксирован ДО единственного прогона на отложенной части. Хэши набора, кода и этого файла — `FREEZE.json`
(коммит до прогона). Повторный прогон на отложенной части с другими настройками запрещён.

## Данные
- Djinni Recruitment Dataset (lang-uk, лицензия MIT; статья Drushchak et al., UNLP 2024 —
  https://aclanthology.org/2024.unlp-1.2/), английские версии:
  вакансии https://huggingface.co/datasets/lang-uk/recruitment-dataset-job-descriptions-english (ревизия b56a6054),
  анкеты кандидатов https://huggingface.co/datasets/lang-uk/recruitment-dataset-candidate-profiles-english (ревизия 86255174).
  SHA-256 parquet — `split_manifest.json`.
- Разбиение по sha256(сид:вид:id): РАЗРАБОТКА 20 % / ОТЛОЖЕННАЯ 80 % (`split.py`, коммит cd7cc1db до любых прогонов).
  Адаптер и выбор флагов — только на разработке (`DEV_LOG.md`).
- Персональные данные: набор открыт и обезличен авторами; сырьё — вне репозитория, в отчёт попадают только id.

## Набор оценки (`build.py holdout`)
- 50 вакансий 11 категорий (Primary Keyword), соответствующих направлениям «Драфта»: Python, Java, .NET, PHP, Node.js,
  Golang → backend; JavaScript → frontend; QA, QA Automation → qa; Data Science → data_ml; Security → security.
  Квоты 5/5/5/5/5/5/4/4/4/4/4. Вакансия годна, если описание ≥ 300 символов; дубликаты текста — одна.
- Пул на вакансию — 200 анкет той же части: 50 той же категории, 75 других категорий наших направлений (трудные
  отрицательные), 75 остальных категорий. Выбор — random.Random(сид:часть:id вакансии).
- Метки (посредники, не люди): 2 — та же категория и стаж анкеты (Experience Years) в диапазоне вакансии (Exp Years:
  no_exp → [0; 2], N y → [N; N+3] при N < 5, 5y → [5; ∞)); 1 — та же категория; 0 — остальное.
  Метки построены по структурным полям Djinni, которые конвейеру НЕ передаются.

## Что оценивается
Продуктовая функция «Драфта» без изменений — `app.modules.matching.bench_upload.evaluate_uploaded_dataset`
(match-v2 ветки А5, режим «без теста»: у кандидатов нет результата теста, грейд не подтверждён, навыки только заявленные
и в балл не входят). На вход — только тексты: вакансия = Position + описание; кандидат = Position + CV.
Адаптер английских текстов (`adapter.py`, djinni-adapter-v1) даёт направление и заявленный грейд по тексту;
кандидаты «вне направлений» (дизайн, менеджмент, DevOps, мобильная разработка …) не загружаются, как в продукте.

Конфигурации (обе — один прогон, отчитываемся обеими):
- **Основная B** «грейд из текста»: `MATCH_UNCONFIRMED_BY_CLAIM=1`, `--mode adapter --need-dir title --need-grade` —
  направление вакансии по названию, грейд вакансии и заявленный грейд кандидата по тексту фильтруют выдачу.
- **Контроль A** «только направление»: флаги по умолчанию, `--mode adapter --need-dir title`.
- Базовые линии на тех же пулах: BM25 (rank_bm25.BM25Okapi, запрос — текст вакансии) и случайный порядок (среднее
  по 100 перестановкам с фиксированным сидом).

## Метрики
nDCG@10 (выгода 2^rel − 1, идеальный порядок — по всем 200 меткам пула); MRR по первой релевантной (≥1 и =2, отсечка 50);
P@5 (≥1 и =2, знаменатель 5 — пустые места нерелевантны). Среднее по вакансиям и 95 % перцентильный бутстреп-ДИ
по вакансиям (10 000 повторов, сид фиксирован); разность «Драфт − BM25» — парный бутстреп.
Главная метрика — nDCG@10 конфигурации B. Порог успеха заранее: нижняя граница 95 % ДИ разности B − BM25 по nDCG@10 > 0.

## Ограничения (пишутся в отчёт)
- Метки — посредники (категория и стаж из анкеты), не оценки людей.
- Режим «без теста» — нижняя граница продукта: главный сигнал «Драфта» (подтверждённый тестом грейд и навыки) здесь
  отсутствует; порядок внутри группы с ядром роли определяется не текстом резюме.
- Тексты английские; основная аудитория продукта — русскоязычная.

## Команда
`cd backend && python ../tools/realdata/djinni/final.py` — проверяет хэши FREEZE.json, собирает набор заново и сверяет
его хэш, запускает обе конфигурации и пишет `docs/realdata/djinni/external_djinni.json`.
