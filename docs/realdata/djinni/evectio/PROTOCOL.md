# Протокол: наш продукт «один в один» на открытом формате внешней оценки соседней команды

Зафиксирован ДО единственного прогона на отложенных частях. Хэши — `FREEZE.json` (данные, наши скрипты, этот файл,
деревья кода продукта в git). Внутренний документ проверки: на сайте соседнюю команду не называем.

## Источник
- Открытый репозиторий соседней команды (лицензия MIT): `github.com/archebaldo777/sporthackathon`, коммит `85bbc78`.
- Подбор: `docs/examples/eval_pairs_example.json` — 48 вакансий (8 их направлений × 6), 620 кандидатов, 5728 пар
  «вакансия × кандидат» с оценкой 0–3. Оценки созданы их генератором синтетических данных по скрытой истине их модели —
  это **посредники, не люди**, и у их ранжировщика здесь «домашнее поле».
- Разбор резюме: `backend/app/validation/data/resumes_labeled.json` (24 резюме, ручная разметка; по нему они дорабатывали
  свой разбор) и `resumes_labeled_test.json` (16 резюме, их отложенный набор).

## Разбиение (до просмотра результатов)
- Подбор: РАЗРАБОТКА — по одной вакансии каждого из 8 их направлений (наименьший `sha256("a17-evectio-2110:" + id)`),
  8 вакансий; ОТЛОЖЕННАЯ — остальные 40. Кандидаты — общая база (протокол «по всей базе» ранжирует всех 620).
- Резюме: РАЗРАБОТКА — их `resumes_labeled.json` (24), ОТЛОЖЕННАЯ — их `resumes_labeled_test.json` (16).
- На РАЗРАБОТКЕ решалось только: правила перевода полей (конфигурация B), таблица «наш тег → навык их онтологии»
  (одно решение по разработке: наш зонтичный тег «HTTP и веб» не переводится в их «HTTP» — 12 лишних из 12).
  Код продукта не менялся. Результаты разработки — `dev_matching.json`, `dev_resume.json`.

## Версия продукта
- «Наш продукт» — код стенда: весь каталог `backend/` совпадает с `integ/2010n` коммит `3f3b2525` (хэш дерева
  `backend` записан в FREEZE; `final_evectio.py` сверяет его и требует пустой `git status` по `backend/`).
  Первый FREEZE (81212113) стоял на гибридном дереве подбора — по замечанию А15 заменён; результаты разработки на коде
  стенда пересчитаны и совпали с прежними до знака (решение про «HTTP» не меняется).

## Подбор
- Продукт вызывается как экран «Принесите свой набор»: `bench_upload.evaluate_uploaded_dataset(json, k=50)` — разбор
  вакансии продуктом (направление, грейд, стек), строгий фильтр по направлению и грейду, ранжирование продукта.
- Конфигурации (обе считаются, ЗАГОЛОВОК — B):
  - A «как есть» — их файл без изменений;
  - B «перевод полей» — `test.grade→grade`, `test.theta→theta`, `test.verified_skills→skills`, `fsp→achievements`,
    `work_formats` (один формат → он, несколько → any), метки `vacancy/candidate → need_id/candidate_id`.
- Метрики — их формула `_metrics` (дословная копия, MIT): P@10, nDCG@10 (выгода 2^rel−1), MRR, R@30; релевантна пара
  с оценкой ≥ 2; вакансии без релевантных пропускаются (как у них). Протоколы — их: «по всей базе» (ЗАГОЛОВОК) и
  «только размеченные пары». Выдача продукта — до 50 строк (MRR обрезается не больше чем на 0,02 на вакансию).
- Сравнение на ТЕХ ЖЕ вакансиях: их ранжировщик и их базовая линия «поиск по резюме» — их код и их окружение
  (`their_eval.py` → их `evaluate_external`). ДИ 95 % — бутстрэп по вакансиям (2000, seed 17), разность с их
  ранжировщиком — парный бутстрэп.
- Срез «общие направления» (5 направлений, которые есть и у нас: Backend, Frontend, QA, Data Science / ML,
  Информационная безопасность) — из того же прогона, не отдельный прогон.

## Разбор резюме
- Продукт вызывается как экран «Загрузить резюме»: `pii.redact(text)` → `extract(red.text)`, языковая модель
  выключена (прогон без ключей, воспроизводим). Поля продукта: ФИО, e-mail, телефон, Telegram, стек, стаж, направление.
- GitHub и город продукт в ответе не выдаёт — показываются как «нет в продукте» (значение None).
- Сравнение и метрики — их `resume_eval.evaluate` дословно (телефон — последние 10 цифр, стаж ±0,5 года,
  micro-P/R/F1 по навыкам). ЗАГОЛОВОК по навыкам — их строгая метрика (все навыки их онтологии); рядом — полнота на
  общей части онтологий (навыки эталона, у которых есть пара среди наших 64 тегов).
- Для сравнения — их разбор на их отложенном наборе (их `evaluate_all`, и их «замер до правок» из файла).

## Ограничение процедуры
- Соль разбиения и результаты разработки попали в один коммит: доказать, что соль выбрана до просмотра результатов,
  нельзя. Риск мал (соль — имя агента и дата, разбиение — по 1 вакансии из каждого направления, 8 из 48), но мы его называем.

## Правила честности
- Один прогон на отложенных: `final_evectio.py` сверяет хэши FREEZE и откажется, если `external_evectio.json` уже есть.
- Никакого выбора лучшего прогона, порогов по отложенным, правок кода продукта после FREEZE.
- В отчёт идут обе конфигурации и оба протокола, где бы мы ни оказались — выше или ниже.
