## Как читать
- «Драфт» выше BM25 по всем пяти метрикам в основной конфигурации; по главной метрике nDCG@10 нижняя граница ДИ разности выше нуля;
  случайный порядок — нижняя граница.
- B против A: фильтр заявленного грейда из текста поднимает метрики «=2» (совпал стаж), это то, ради чего он включается;
  по «≥1» конфигурации на уровне друг друга.
- Слабые места (по категориям): смежные категории внутри одного направления (QA ↔ QA Automation, Node.js ↔ JavaScript,
  PHP) и вакансии, где фильтр грейда оставляет меньше 10 кандидатов. Исправление — в продукте подбора (зона А5),
  адаптер этого не делает.

## Метод (подробно — PROTOCOL.md)
- Оценивается продуктовая функция без изменений: `evaluate_uploaded_dataset` (match-v2 ветки А5, режим «без теста»).
  Хэши продуктового кода подбора, каталога, разбора резюме и профилей — в FREEZE.json.
- На вход — только тексты (Position + описание вакансии / Position + CV); структурные поля Djinni скрыты и используются
  только для меток. Адаптер (`adapter.py`, djinni-adapter-v1) даёт направление и заявленный грейд по английскому тексту;
  настраивался только на разработке (20 %), журнал — `DEV_LOG.md`.
- Разбиение по sha256 (сид a17-djinni-2026-10-21) закоммичено до любых прогонов (cd7cc1db, `split_manifest.json`).
- Базовые линии: BM25 (rank_bm25) и случайный порядок на тех же пулах.

## Ограничения
- Метки — посредники, не люди: «та же категория» и «стаж в диапазоне» не равны «подходит работодателю».
- Режим «без теста» не показывает главный сигнал «Драфта» — подтверждённые тестом грейд и навыки; внутри группы с ядром
  роли порядок не зависит от текста резюме (заявленное в балл не входит — правило продукта).
- Английские тексты одного рынка; 50 вакансий — широкие ДИ по отдельным категориям (4–5 вакансий в каждой).
