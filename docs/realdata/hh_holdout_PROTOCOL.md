# Отложенный набор hh.ru — протокол проверки (зафиксирован до прогона, 21.10.2026)

Набор: `docs/realdata/hh_holdout_corpus.json`, 381 вакансия, SHA-256 манифеста `db648a18…` (`hh_holdout_FREEZE.json`).
Этот файл закоммичен **до** прогона; после прогона он не меняется.

## 1. Главные величины (прогон `hh_holdout.py run`, один раз)
- **Направление разобрано верно** — доля вакансий, где направление из разбора текста совпало с меткой hh.ru
  (роль hh.ru + слова направления в названии), среди вакансий направлений каталога. Знаменатель — все такие вакансии.
- **Грейд разобран верно** — доля совпадения грейда из разбора со словом грейда в названии вакансии (только вакансии со
  словом грейда в названии).
- **Ключевые навыки найдены** — доля «Ключевых навыков» hh.ru (в справочнике платформы), найденных разбором текста.
- Подбор (подборка непуста, есть подтверждённый кандидат точной категории, покрытие обязательного в пятёрке) — на
  **модельном** пуле демо-мира (2 660 модельных кандидатов, из них 2 160 со связками навыков hh.ru — E2); подпись
  «модельный пул», это проверка механики, а не рынка.

## 2. Независимая проверка спорных меток (команда `hh_holdout.py adjudicate`, один раз, после прогона)
Метки hh.ru шумные (на наборе разработки: «охрана труда» и «противопожарная безопасность» в роли «информационная
безопасность», Data Engineer с ролью DevOps и т. п.). Для КАЖДОГО расхождения «разбор ≠ метка» по направлению и грейду:
1. Два арбитра — модели двух разных компаний: `anthropic/claude-sonnet-5.5` и `openai/gpt-6.1-sol`, температура 0.
2. Арбитр видит только название и текст вакансии (первые 3 000 знаков) и список вариантов: 9 направлений каталога +
   «не IT-вакансия» (для грейда — intern, junior, middle, senior — lead и тимлид считаются senior, как в метке, — и «не указан»). Ни метку hh.ru, ни ответ разбора
   арбитр НЕ видит.
3. Итоговая метка — только если оба арбитра ответили одинаково; если разошлись или ответ не из списка — остаётся метка
   hh.ru (консервативно, в пользу «ошибки разбора»).
4. Совпавшие разбор и метка не перепроверяются (оба верны — допущение, указывается в подписи).

Величины после проверки (рядом с главными, не вместо них): «направление верно после проверки спорных меток двумя
моделями» = (совпадения разбора с меткой hh.ru + расхождения, где итоговая метка = ответ разбора) / знаменатель; та же
формула для грейда; доля шумных меток = расхождения, где итоговая метка ≠ метка hh.ru, / знаменатель. Подпись: «модели,
не люди». Все ответы арбитров — в `docs/realdata/hh_holdout_adjudication.json` (номер вакансии, ответы, итог; без
текста вакансии).

наборе. Следующая проверка — новый отложенный набор (новая дата `date_from`, новый файл).
