# Второй отложенный набор hh.ru — протокол проверки (зафиксирован до прогона, 21.10.2026)

Зачем второй набор. Первый отложенный набор (`hh_holdout_corpus.json`, 381 вакансия, прогон c54006180, протокол
`hh_holdout_PROTOCOL.md`) использован: после его единственного отчёта на нём (и на наборе разработки) настраивался
классификатор направления dir-v2 — правило «роль, прямо названная в названии вакансии» (`need_parser.title_role_direction`,
флаг `NEED_TITLE_ROLE`, по умолчанию включён). Поэтому первый набор для dir-v2 — обучающий, а честная цифра dir-v2 —
только на новом наборе, которого не видел ни словарь, ни классификатор.

Набор: `docs/realdata/hh_holdout2_corpus.json`; хэш манифеста — `docs/realdata/hh_holdout2_FREEZE.json` (поле
`manifest_sha256`). Этот файл и FREEZE закоммичены **до** прогона; после прогона они не меняются.

## 0. Отбор (команда `hh_holdout.py --tag 2 collect --per 12 --date-from 2026-10-11`)
Тот же отбор и та же разметка, что у набора разработки и первого отложенного (`hh_plus.collect`): GET /vacancies по
9 направлениям × 4 грейда, роль hh.ru + слова направления и грейда в названии, вся Россия, опубликованы с 2026-10-11, до
12 на ячейку, добор — по опыту hh.ru; страницы поиска 0–5. Исключаются вакансии набора разработки (414) **и** первого
отложенного набора (381) — по номеру, по SHA-256 текста и по паре «работодатель + название»; дубли текста внутри набора —
тоже. Тексты вакансий в репозиторий не входят (только номера, ссылки, хэши текстов и метки).

## 1. Главные величины (прогон `hh_holdout.py --tag 2 run`, один раз)
Код прогона — голова ветки `ag/a5-matching` на момент прогона (в `hh_holdout2_RUN.json`), продукт по умолчанию:
`NEED_TITLE_ROLE=1` (dir-v2), `CATALOG_EXT_ENABLED=1` (9 направлений), `HH_MATCH_COMPARE=0`, разбор правилами без LLM.
- **Направление разобрано верно** — доля вакансий, где направление из разбора текста совпало с меткой hh.ru (роль hh.ru +
  слова направления в названии), среди вакансий направлений каталога. Знаменатель — все такие вакансии. **Это та цифра
  направления, которая идёт на сайт** (одна), с условием: «отложенный набор N вакансий hh.ru, метки — поля hh.ru, прогон
  один, дата, команда пересчёта».
- То же — по направлениям (особо: инженерия данных, аналитика, информационная безопасность — пункт P1-5 задания).
- **Грейд разобран верно** — доля совпадения грейда из разбора со словом грейда в названии (только вакансии со словом
  грейда в названии).
- **Ключевые навыки найдены** — доля «Ключевых навыков» hh.ru (в справочнике платформы), найденных разбором текста.
- Подбор (подборка непуста, есть подтверждённый кандидат точной категории, доля кандидатов без ФСП в пятёрках) — на
  **модельном** пуле демо-мира (свежий сид демо-мира того же кода); подпись «модельный пул», это проверка механики, а не
  рынка.

**Контроль «до/после» в том же прогоне** (записан здесь до прогона): тот же код и тот же набор, направление дополнительно
разобрано с `NEED_TITLE_ROLE=0` (без правила dir-v2, только разбор, без подборки) — поле `direction_control` в
`hh_match_holdout2.json`. Разница «dir-v2 − контроль» — эффект dir-v2 на невиденных вакансиях. Контроль — в отчёте и
документации, на сайт не выводится.

## 2. Независимая проверка спорных меток (команда `hh_holdout.py --tag 2 adjudicate`, один раз, после прогона)
Тот же порядок, что в первом протоколе (`hh_holdout_PROTOCOL.md`, п. 2):
1. Два арбитра — модели двух разных компаний: `anthropic/claude-sonnet-5.5` и `openai/gpt-6.1-sol`, температура 0.
2. Арбитр видит только название и текст вакансии (первые 3 000 знаков) и список вариантов: 9 направлений каталога +
   «не IT-вакансия» (для грейда — intern, junior, middle, senior, «не указан»). Ни метку hh.ru, ни ответ разбора арбитр
   НЕ видит.
3. Итоговая метка — только если оба арбитра ответили одинаково; иначе остаётся метка hh.ru (консервативно).
4. Спорные — расхождения «разбор ≠ метка» и основного разбора (dir-v2), и контроля; каждая пара (вакансия, поле)
   проверяется один раз, итоговая метка общая для обоих вариантов. Совпавшие разбор и метка не перепроверяются.

Величины после проверки — рядом с главными, не вместо них, с подписью «метки спорных вакансий проверены двумя моделями,
не людьми»: (совпадения разбора с меткой hh.ru + расхождения, где итоговая метка = ответ разбора) / знаменатель — для
dir-v2 и для контроля; доля шумных меток. Ответы арбитров — `docs/realdata/hh_holdout2_adjudication.json` (номер,
ответы, итог; без текста вакансии).

наборе; выбирать между прогонами (прогон один). Следующая проверка — новый отложенный набор (новый файл).
