# Протокол: «один в один» на открытом генераторе Dev_dev (до прогона)

Цель — сопоставимая цифра: наш подбор и их IT Match на одном мире, одном тесте, одних метках и одной процедуре оценки.
Синтетика (модель), не люди. Внутренний документ подбора; на сайте соперника не называть («открытый генератор
другого решения, MIT»).

## Что берём у них без изменений
- Репозиторий https://github.com/LaimOr127/Digital-platform-aggregator-of-IT-vacancies-FSP- (MIT), коммит
  `dec3f95449d2f89972bd99f5b6fb661ddd836cea`, модуль `backend/app/evaluation/matching_eval.py`.
- Мир `run(seed, 40 вакансий, 1000 кандидатов)`: популяция, их тест (`confirmed_level`), вакансии, метка
  `_relevance` (2 — направление, грейд равен, есть хотя бы один навык стека вакансии; 1 — соседний грейд или нет стека;
  0 — иначе), метрики P@5, P@10 (по метке 2), nDCG@10 (выгода 2^g − 1, идеал по всей популяции), «переоценённые в
  топ-10» (истинный грейд ниже вакансии). Их три выдачи считаются их кодом в том же процессе; их числа
  воспроизводятся до знака (зерно 2026: IT Match P@5 77,0 %, P@10 73,8 %, nDCG@10 0,828, переоценённых 6,0 % — как в их
  отчёте `python -m app.evaluation --seed 2026`).
- Наш подбор — четвёртая выдача в их же `_evaluate`: тот же поток ГСЧ для разбивки равных (после их трёх выдач).
  Обёртки над их кодом ГСЧ не трогают: `evaluate` — счёт «верно / всего» по навыкам, `confirmed_level` — исход теста.

## Что получает наш подбор (только наблюдаемое — то же, что их IT Match)
Переводчик полей — `tools/realdata/devdev/rank_ours.py` (правила в его описании): направление 1:1 (mobile, devops —
направления расширения каталога), грейд 1:1 (Lead — расширение грейдов), результат теста их шкалы → наша
(θ − 2,5; пороги грейдов совпадают с шагом 1), навыки заданий теста с «верно / всего» → подтверждённые тестом,
навыки анкеты → заявленные (в балл не входят), «подтверждено ФСП» elite / advanced / base → всероссийское 1 / 3 место /
региональное участие, вакансия → текст «{Грейд} {направление}. Стек: …» + направление и грейд полями формы. Город,
формат и зарплата не передаются: их IT Match порядок по ним не меняет, их метка от них не зависит. Навык, которого не
знает наш словарь (их «machine-learning», «data-analysis», «qa-automation», «information-security»), отбрасывается —
так поступил бы продукт.

## Строки (фиксируются здесь, до прогона)
| строка | конфигурация | выбор работодателя |
|---|---|---|
| **main** (главная) | финальный стенд: MATCH_V2=1, CATALOG_EXT_ENABLED=1, GRADES_EXT_ENABLED=true | по умолчанию |
| exact | то же | «строго запрошенный грейд» (`filters.grade_exact`) |
| base (справочно) | без расширения каталога и Lead | по умолчанию |

«Строго запрошенный грейд» — новая опция API подборки (по умолчанию выключена): внутри яруса статуса грейда и ступени
стека — порядок по вероятности (по θ и SE теста), что уровень именно запрошенный; никто не скрывается; в объяснении —
эта вероятность. Их метка считает кандидата на грейд выше «частично подходящим» (1), наша основная метка — «подходит»
(правило методиста: сильнее запроса работодатель не теряет); опция — честный способ для работодателя сказать «нужен
именно Middle». Поэтому строка exact — отдельно, главная — main.

## Зёрна
- Разработка переводчика и опции: 1, 2, 3 (видели до FREEZE, см. ниже).
- Отложенные (ни одна наша выдача на них не запускалась): **2026** (их опубликованный отчёт) и 77021161–77021165.
- Итог — по 240 вакансиям 6 отложенных зёрен (бутстрэп по вакансиям, 2000 повторов, зерно 7702116; разность
  «мы − IT Match» — парная по вакансии) и отдельно по зерну 2026 (прямое сравнение с их 0,83).

## Что видели на зёрнах разработки 1–3 (120 вакансий) — до FREEZE
- Выбор источника θ: «исход теста подтверждённого уровня» (то же, что видит IT Match) против «всех ответов пути одной
  оценкой» — второй хуже (nDCG@10 0,757 против 0,776 по default, среднее по зёрнам); взят первый.
- Варианты опции «строго запрошенный грейд»: A — сильнее запроса (in_band < 0,5) ниже: nDCG 0,833; B — то же по
  вероятности < 0,5: 0,833; C — порядок по вероятности «уровень именно этот»: 0,879. Взят C.
- Итог разработки: main nDCG@10 0,776 (IT Match 0,874; разность −0,098 [−0,117; −0,079]), P@5 0,675 (0,822);
  exact nDCG@10 0,879 (разность +0,005 [−0,014; +0,021]), P@5 0,862 (0,822; +0,040 [+0,008; +0,073]), MRR 0,942
  (0,920), переоценённых в топ-10 8,2 % (4,5 % — хуже, +0,037 [+0,020; +0,053]); base nDCG 0,519.
- Главная причина проигрыша main — кандидаты на грейд выше в топе (их метка 1, наша 2): разбор — 96 из 124 мест
  без метки 2 в топ-10 на зерне 1 (первый вариант переводчика, до написания «Go» с заглавной — строчное «go» наш
  словарь как слово не берёт).

## Правило одного прогона
`python3 tools/realdata/devdev/devdev_1to1.py freeze` пишет `docs/realdata/devdev_1to1_FREEZE.json` (хэши кода
подбора, переводчика, протокола, их коммит, зёрна, строки) → коммит → проверка А15 → «ок» → один
`devdev_1to1.py run` (отказывается при несовпадении хэша и при существующем результате). Результат публикуется при
любом исходе, все три строки и обе стороны.
