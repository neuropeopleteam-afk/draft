# README 2 — что изменилось к финалу и как это проверить

Короткая версия для экспертов. Основной документ — [README.md](README.md); подробная история доработки по волнам —
[`docs/submission/CHANGELOG.md`](docs/submission/CHANGELOG.md).

На отборе в этом файле были цифры, вписанные вручную, и обещания функций, которые мы не могли показать. К финалу мы
от этого отказались: здесь и в README каждая цифра подставлена сборкой из [`docs/NUMBERS.json`](docs/NUMBERS.json)
вместе с условием (на ком измерено, объём, дата, команда пересчёта), а сборка останавливается, если цифры нет в
файле или ссылка ведёт на несуществующий файл, тест или метод API.

## Что изменилось к финалу — главное

| Было на отборе | Стало к финалу | Где проверить |
|---|---|---|
| Цифры точности вписаны в текст вручную | Все цифры — из одного файла, с условием и командой пересчёта; протокол и хэш данных — до прогона, отчётный прогон — один | `/validation`; `docs/NUMBERS.json`; раздел 5 [документации](docs/submission/DOCUMENTATION.pdf) |
| Порядок в подборке смешивал тест, стек и заявленное в резюме | Место внутри категории задают тест по навыкам вакансии и подтверждённые достижения ФСП; заявленное без теста на место не влияет | `/employer/needs/<id>` → «Выше следующего кандидата за счёт: …»; `docs/matching/ORDER.md` |
| Одна строка цифр | Каждая метрика — дважды: в стандартных условиях и в проверке на прочность | таблица ниже; `/validation` |
| Демо-данные рядом с настоящими | Рыночный режим: настоящий аккаунт не видит демо; демо для экспертов — в `/demo`, у каждого своя песочница | `/register` на свой ящик; `/demo` |
| Банк заданий без автоматической проверки | 1 646 семейств заданий; каждое семейство генерирует свои варианты, ключи проверяются автоматически и не уходят в браузер | `make test-bank`; `e2e/tests/21-no-answer-keys.spec.ts` |
| Достижения ФСП со слов кандидата | Достижение — со ссылкой на строку официального протокола; без истории ФСП — ноль, без штрафа | `/candidate/fsp`; `/demo` → профиль без истории ФСП |
