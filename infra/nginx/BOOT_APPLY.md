# Я16 — что применить на сервере «Москва» (устойчивая загрузка интерфейса)

Файл для штаба. Исполнитель Я16 на сервере ничего не менял (только чтение). Все команды ниже — для выкладки штабом.

## Что было (10.10, журнал nginx и заголовки стенда, main 2877ca9)
- Основной файл `assets/index-*.js` — 1 227 047 Б, на проводе 418 295 Б: контейнер `web` сжимает «на лету»
  (gzip уровня 1), ответ `Transfer-Encoding: chunked` без `Content-Length`; два заголовка `Cache-Control`
  (`max-age=31536000` от `expires` и `public, immutable` от `add_header`).
- Неполные ответы «200» 13:06–13:25: 163 275 … 261 579 Б (шаг 16 384 Б). Замер штаба: соединения из-за рубежа
  (VPN, облачные браузеры, песочница) с «Москвой» обрываются на ~16 КБ; через «Мадрид» тот же файл — 418 КБ за 0,6 с.
- `index.html` подключал `/recover.js` блокирующим скриптом в `<head>`; его таймер запускался только по `load`,
  а при зависшем модуле `load` не наступает — белый экран без сообщения.

## Шаг А — обязательный: выкладка ветки fix/boot (правка хоста не нужна)
Всё нужное — внутри образа `web` (frontend/Dockerfile копирует `frontend/nginx.conf` и `dist`):
- сборка кладёт рядом с файлами `.gz` (уровень 9) и `.br` (vite.config.ts, плагин precompress);
- `frontend/nginx.conf`: `gzip_static on` — файлы сборки уходят сжатыми заранее, с `Content-Length`
  (оборванную передачу браузер видит как ошибку — сторож сразу повторяет загрузку, а не ждёт), один заголовок
  `Cache-Control: public, max-age=31536000, immutable` для `/assets/`, `no-cache` для `/`, `/index.html`, `/sw.js`;
  нет файла сборки — 404 (не index.html).

```bash
cd /opt/spectrek_fsp/app && docker compose build web && docker compose up -d web
# проверка (только чтение; пароль — из переменной, в вывод не попадает):
BASIC_USER=demo BASIC_PASSWORD="$(cat <файл с паролем стенда>)" bash infra/nginx/check-boot.sh https://fsp.neuropeople.pro
bash infra/nginx/check-boot.sh http://127.0.0.1:8140      # контейнер напрямую, без внешнего nginx
```
Ожидаемо: «проваленных проверок: 0», стартовый JS на проводе ≈ 95,6 КБ (index ≈ 41,8 КБ + vendor ≈ 53,8 КБ).
На стенде до выкладки та же проверка даёт 5 провалов (сторожа нет, блокирующий recover.js, chunked без
Content-Length, два Cache-Control) — `reports_0910/boot.md`.

Фрагмент «без пароля» для живой демонстрации (`fsp.neuropeople.pro.jury-live.conf`) менять не нужно: сторож встроен
в index.html, новых файлов вне `/assets/` нет; `/recover.js` остаётся в сборке для вкладок прежней версии.

## Шаг Б — по решению владельца: HTTP/2 на внешнем nginx (рекомендация Я16 — НЕ включать до сдачи)
Правка (nginx 1.24 на хосте понимает только параметр `listen`; директива `http2 on;` — с 1.25.1):
```nginx
# /etc/nginx/sites-available/fsp.neuropeople.pro, блок server 443
listen 443 ssl http2;
```
`sudo nginx -t && sudo systemctl reload nginx`; откат — убрать `http2`, `nginx -t`, reload.

Почему не сейчас:
1. Параметр `http2` относится к сокету `*:443`, а на нём ещё три сайта (densito-ru, densitoai, vk.neuropeople.shop) —
   включится и у них.
2. При обрыве ~16 КБ на соединение HTTP/2 хуже, а не лучше: всё (страница, JS, CSS, API) идёт по одному TCP-соединению;
   зависло оно — зависло всё, и повторная загрузка браузер переиспользует то же соединение. С HTTP/1.1 повторная
   загрузка открывает новые соединения — именно поэтому 10.10 «повторная навигация помогала».
3. Выигрыш для нашей страницы мал: на старте 3 файла (index.html, index, vendor) + CSS и шрифты; ленивые экраны
   грузятся по одному при переходе — с keep-alive HTTP/1.1 это те же соединения.
Если владелец решит включить — после выкладки 5, с проверкой `curl --http2 -I` и снимком стенда из РФ и через VPN.

## Шаг В — по желанию, не до сдачи: brotli
`.br` уже лежат в образе (стартовый JS 80,9 КБ против 95,6 КБ gzip), но в `nginx:1.27-alpine` нет модуля
ngx_brotli, а внешний nginx (1.24 Ubuntu, без модуля) проксирует в контейнер и файлов не видит. Варианты: образ web
со сборкой ngx_brotli (+ `brotli_static on;` в frontend/nginx.conf) либо раздача `/assets/` внешним nginx с диска
(`libnginx-mod-http-brotli-static`). Оба — правка выкладки; −15 КБ на старте не стоят риска до 11.10.

## Service worker (проверено, правка не нужна)
`public/sw.js`: навигация — сначала сеть; кэш `/` — только при обрыве сети или 5xx, и это index.html той же версии,
что и закэшированные при установке файлы сборки (кэши прежних версий удаляются при активации, VERSION — на каждую
сборку). Устаревший index при работающей сети SW не отдаёт. Если после выкладки вкладка держит прежний index, а
файла ленивого экрана уже нет (404) — экран «Раздел не загрузился» и одна повторная загрузка с `?r=` (сторож снимает
SW и кэши, как прежний recover.js) — новая версия.
